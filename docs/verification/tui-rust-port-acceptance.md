# tui-rust-port — Final Acceptance Report

Status: **ACCEPTED** — verified 2026-08-07 (final re-verification on the merged
`claude/tui-rust-port` branch, PR #114).
Scope: 1:1 TypeScript→Rust port of `tui/` → the Rust crate at **`tui/`** (bin
`future-tui`, lib `future_tui`) — identical UI rendering / key handling /
interaction / argument parsing / help text, with a **self-implemented terminal
backend** (no crossterm; `libc` on POSIX, `windows-sys` console API on Windows),
ported TS unit tests, a golden render harness, and tmux screen-consistency
tests. The TypeScript TUI is **retired** (same as the CLI, 2026-08): its
render + screen outputs are committed as goldens under `tui/tests/golden/`,
recorded before the TS sources were deleted. The crate consumes
`future-rpc::proto` (the single proto codegen owner, PR #112) instead of
owning generated code.

## 2. Divergence list (known / accepted)

1. **Link reference definitions inside blockquotes/list items** keep their surrounding
   blank-line spacing only at the top level — pulldown-cmark consumes definitions
   differently inside containers than `marked`. Documented in
   `tui/src/components/markdown.rs`; **not exercised by the corpus**.
2. **Live rendering depending on timestamps / random ids** (`allocateImageId`, `newId`) is
   excluded from the render corpus — ids are supplied explicitly.
3. **Windows backend is type-checked, not runtime-tested**: the `windows-sys` console
   implementation (raw mode / VT input+output / resize via window-size events) passes
   `cargo check --target x86_64-pc-windows-msvc` (the CI 3-platform gate) but has not
   been exercised on a real Windows console (documented in `tui/src/terminal_windows.rs`).
4. **TS event-loop machinery is mapped to the app loop** rather than ported literally:
   the 20 ms autocomplete debounce / `AbortSignal` cancellation are expressed as the
   app's 33 ms render scheduler + 20 ms autocomplete debounce timer — observable behavior
   (debounce, cancellation, ordering) is identical, verified by the tmux scenarios.

## 3. Bugs the harnesses caught (all fixed, regression-tested)

Rendering/behavioral divergences found by byte-comparison and fixed in the port:

- **h1 heading style composition order** — TS applies `heading(bold(underline(t)))`
  (fg, bold, bold, underline); the port had `heading(underline(bold(t)))`. A stale unit
  test had encoded the wrong order; corrected.
- **queued suffix inside `dim()`** — TS renders `dim("queued (#n)")` with the suffix
  inside the dim span; the port reset the style before the suffix.
- **paragraph trailing whitespace** — pulldown-cmark trims trailing spaces from `Text`
  events; `marked` keeps them. The paragraph adapter restores the source slice's
  trailing whitespace.
- **table column-width "shrink to fit" + remainder distribution** — must use SIGNED
  arithmetic (`remaining - allocated` goes negative in JS and skips the loop; `usize`
  underflowed → debug panic).
- **footer token stats JS truthiness** — TS renders `↑/↓/R/W` stats only when truthy,
  so a zero value is skipped; the port rendered `R0 W0` for `Some(0)`. Now guarded with
  `n > 0` on all four stats.
- **status overlay session/model fallbacks** — TS renders `**Session:** ${s.sessionId ||
  "(none)"}` (either-or); the port always appended ` or (none)` / ` or (unknown)`.
- **spurious "Connection to agent lost" flap after welcome** — the 5 s connect watchdog
  must be armed ONCE and cleared on first data (never re-armed; long-term dead streams
  are the 10 s heartbeat's job), and poke-driven resubscribes must be silent (TS cancels
  the old stream and ignores its stale end/error handlers). Both fixed with regression
  tests (in-process tonic mock server: `idle_stream_does_not_flap_after_first_data`,
  `session_change_resubscribes_silently`).

```bash
make test-tui-diff            # render parity vs golden, 97/97 (rustup 1.97.0; no bun)

rustup run 1.97.0 cargo fmt --check

```

Notes: Homebrew cargo ignores `rust-toolchain.toml` — always run under
`rustup run 1.97.0`. Unset leaked `FUTURE_VERSION` (`env -u FUTURE_VERSION`) so builds
(and the Rust `--version` string) are deterministic. `make test-tui-tmux` must run in an
environment with tmux + a working PTY (local machine, not headless CI). The TypeScript
TUI is retired; the goldens are the reference (re-record with
`tui/tests/diff-ts-rust.sh --record` / `tui/tests/tmux-diff.sh --record` only when
intentionally changing screens).
