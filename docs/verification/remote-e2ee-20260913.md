## Historical Windows baseline failures — resolved by integrating #596

The first full desktop `cargo test` was attempted before #596. Besides then-fixed v2 fixture updates,
it failed in unchanged Windows path/Git fixtures and exceeded the command time
budget before printing a final full-suite summary. A clean, detached worktree at
`05da063a` independently reproduces:

- `git_review::tests::git_output_returns_stdout_and_errors_on_failure`:
  `git_review.rs:600`, `File::set_modified` on a read-only-opened handle returns
  Windows error 5 (`PermissionDenied`).
- `commands::files::tests::best_effort_canonical_resolves_each_shape`:
  expected `/definitely/not/here/x/y/z.txt`, got the Windows canonical
  `\\?\D:\definitely\not\here\x\y\z.txt`.
- The `canonical_or_raw_canonicalizes_existing_and_falls_back` Git fixture also
  reproduces the same `set_modified` error on that clean baseline.

Those files are unchanged by the E2EE branch. This is evidence for those specific
baseline failures, not a blanket claim that every full-suite failure is harmless.
The later upstream fix `824e0243` (#596) resolves the Windows baseline issues.
After merging it, preserving encrypted test assertions and matching disconnect
notifications rather than assuming arrival order, the full Windows suite passed
with the counts above. The earlier scoped pass was not substituted for that run.
