## 1. 不可突破的目标

1. 实时生成、输入、滚动、切换和取消保持响应。持锁广播、渲染和数据库 writer 内不做整轮正文转换。
2. 已确认接收的用户输入、执行/审批必要边界和已确认完成的运行都有持久提交依据。持续保存正文，缩小崩溃未提交尾部。
3. 已发布历史结构兼容；不为精简扫描、压缩、重新编码或重写已入库的历史正文。新会话从首次写入使用精简结构。
4. 结束只封闭内容块并提交终态；不生成整轮快照、不合并历史段、不集中删除原始事件。
5. 消息、工具详情、模型上下文、重连和恢复共用一份持久正文。SQLite 是唯一持久数据源，不增设文件日志及导入链。

实时显示允许领先于磁盘提交，突然崩溃仍可能丢失未提交尾部。严重存储落后时背压/中断生产端，界面和取消仍须可用；不虚报保存或无限缓存。
模型上下文摘要、历史检索、附件和 fork/reset 的原有产品语义继续保留。

## 2. 与上一版逐项 review

| 项目 | 上一版及前一轮建议 | 本次定稿 |
|---|---|---|
| 正文单份保存 | 不可变段、引用共享已实现 | 保留，不改为可变尾页，不靠减少落盘频率攒大段 |
| 主要优化对象 | 曾从小段数量推测开销 | 以实际 B-tree 页占用排序，优先处理重复变更 JSON、长键索引和单字段链接 |
| 变更编码 | 每批薄 JSON，仍重复长标识 | 稳定上下文一次保存，变更以短键/数值列引用；未知扩展无损保留 |
| 单正文增量 | 变更行加独立正文链接行 | 常见单字段增量直接保存范围；多字段事实使用扩展链接 |
| 读取 | 已有有界 reader/传输/分时解码 | 保留；每页批量取上下文和扩展链接，禁止 N+1 查库或逐行重复解析上下文 |
| 版本策略 | 前一轮建议增加运行级编码版本兼容旧候选 | 删除该兼容层：上一版未发布，直接修订目标布局，不设计旧候选升级/双写/双解码 |
| 历史迁移 | 上一版已有通过记录 | 发布过的 Agent/Desktop/导入/备份路径全部列为重新测试的阻断门槛 |
| 空间验收 | 合成样本及运行期间测量 | 原记录留存不覆盖；新实现在同负载独立测量，分别报告数据库、WAL、索引及写入时延 |

旧计划中的实施过程和“已完成/默认关闭”状态属于归档，不能作为本修订的实现状态。
上一版测试通过只说明上一版，不证明本次上下文归属、回收和历史迁移仍正确。

## 3. 证据与收益范围

新会话的只读审计中：`stream_changes` 分配 660 KiB，正文段表 104 KiB，工具关联索引 88 KiB，正文链接及其反向索引分别 56/40 KiB。
1542 个正文段共享 SQLite 页，不能按“每段一页”推算空间。正文总计 66,086 字节，变更共 1730 条。

内存布局原型保留全部 1730 条变更、原始时间戳字符串和未知 JSON，全部元数据语义还原一致。
计入候选索引后，所比较的元数据结构从 921,600 降至 385,024 字节，减少 58.2%；1522 条增量使用直接范围，70 条字段链接留在扩展结构。
它没有实现 RPC、故障恢复、迁移或回收，也未测量 WAL/CPU/UI；不能当作全库节省比例或发布结果。
详见[基线记录](stream-storage-space-baselines.zh-CN.md)。后续自动验收使用合成负载，不提交个人正文或会话标识。

## 4. 版本与历史边界

| 数据来源 | 支持方式 |
|---|---|
| 已发布 Agent schema 2–7 | 冻结原始夹具；按受支持升级链进入最终布局，既有会话仍为 legacy 格式 1，原正文和事件不转换 |
| 已发布 JSONL/事件来源、skills-only bootstrap | 保留既有导入/准入契约；导入历史保持 legacy，跳过/重复/墓碑规则不变 |
| 已发布 Desktop 布局及 contract 1–3 | 保留已发布 SQL、校验和、身份和事务边界；进入本轮最终目标契约 |
| 空库、新会话 | 直接创建最终紧凑布局；新会话使用逻辑格式 2 |
| 上一版未发布 schema 8/格式 2 开发库 | 不提供升级、兼容解码或转换；不匹配时明确拒绝并保留原文件 |

当前未发布的 Agent schema 8、Desktop contract 4 和格式 2 目标可直接调整，不为兼容上一版新增 schema 9 或运行级双编码。
最终编号由发布账本核实；已经发布的版本、夹具和迁移校验和绝不可改写。

同为开发版 `user_version=8` 不能表示结构一定相同。最终库写入明确的布局标记，并检查必要表/列/外键/索引；不匹配的非空开发布局在初始化、WAL 配置和补表之前拒绝。
不得通过创建空新表、伪造兼容列、自动删除数据库或重置 home 掩盖不兼容；也不得假报迁移成功。
现有开发测试库如包含真实历史，原文件继续保留，可由原候选读取；新布局验证使用隔离数据根或受支持的发布版备份副本，不自动清空用户数据。

“不为精简改写历史”不取消已发布迁移中必要的旧 JSONL 导入、GUI 无损归档及备份读写。
这些原契约仍按原顺序执行、保留字节，不借本次优化新增历史压缩或启动全量正文整理。

## 5. 最终数据模型

以下名称为逻辑契约；M1 冻结精确 DDL、索引、列编码和约束，不能直接把原型 SQL 当生产 schema。

| 对象 | 内容与约束 |
|---|---|
| 会话/运行 | 数据库身份、恢复代次、会话格式、运行 epoch/次序/状态和持久水位，保持现有语义 |
| 不可变上下文 | 运行内稳定的消息、工具、块、内容键及必要类型/字段存在性；短整型 ID；相同上下文复用，变化则新增版本 |
| 紧凑变更 | 流身份、上下文 ID、起止游标、固定事件码、时间、标志、必要的正文范围及剩余字段 |
| 多字段链接 | 低频语义事件的字段/编码/正文范围；常见单字段增量不再重复保存一条链接 |
| 正文对象/段 | 保留长度、封闭摘要、UTF-8 不可变段和共享引用；不重复写模型摘要或已流式保存的最终正文 |
| 历史展示索引 | 只保存有用的顺序/关联/薄元数据，不持有正文副本；只读分页不填全历史缓存 |

上下文的范围至少包含会话、run、epoch 及其稳定字段；同一文本键不能跨运行或跨消息误复用。
事件码和已知字段码采用冻结显式数值，不依赖 Rust enum 声明顺序。上下文 ID 与正文 ID 都不是跨会话读取授权。
未知事件、未知块和多字段扩展必须有通用表示；不能因不符合高频路径而静默截断、丢弃或猜测默认值。

上下文唯一性由完整语义键/描述符核验；摘要可以加速查找，不能以哈希相等代替冲突检查。
稳定的长外部标识保存在上下文或权威消息表中，热变更及索引优先引用短键。

## 6. 无损编码与协议不变

- 固定字段只从明确的白名单提取；剩余字段保留在有字节上限的扩展 JSON/正文引用中。
- 字段不存在、显式 null、空字符串、空数组和 false 必须可区分；存在性标志有固定编码。
- 第一轮保留原始时间戳字符串；若后续改整数，必须保留原有精度和必要表示信息，不以截断到毫秒换空间。
- provider 签名、opaque 内容、原始 JSON 字符串按要求保留原字节；普通元数据对象按语义一致验证，不能将二者混淆。
- 思考签名、工具错误/中断标志、多模态附件、未知扩展、审批决定和计费事实不能因 UI 不显示而删除。
- 正式版只省略经保留矩阵证明为诊断冗余的概率分布、重复审计载荷等；调试开关有范围和上限，不改变恢复真源。
- 对外事件、内容键、字段路径、游标和范围契约保持一致；数据库适配层还原协议。无法无损表达的数据使用通用扩展路径或明确拒绝，不降级为空历史。

现有 `segmented_content_v1` 能力可在语义不变时保留；存储 schema 准入、逻辑会话格式、线上 RPC 能力分别管理。
所有本地/远程消费者仍需重新验证，不能仅凭原型 JSON 往返一致宣布协议兼容。

## 7. 写入、事务与崩溃一致性

保留专用 writer、有界队列、独立实时推送和现有关键边界。上下文查找/编码在持久化路径完成，不进入广播/会话锁的长临界区。
同批相邻增量按相同上下文和连续偏移合并；跨消息/工具/epoch/语义边界不合并，不重排原游标。

一次发布事务必须原子包含：新上下文、所需正文段/范围、紧凑变更、必要链接和持久水位。
大正文仍可分批暂存，但引用未完整提交前不推进水位。重试按逻辑身份、原偏移、正文和完整字段集合核验。
不以忽略唯一冲突或重新分配短 ID 掩盖不同数据。

上下文缓存有容量/字节限制，cache miss 用索引查询；只有提交后的 ID 可以供后续批次复用。
提交前分配但随后回滚的 ID 必须失效；崩溃重启从已提交上下文重新解析，缓存不是持久数据源。

| 边界 | 保持的行为 |
|---|---|
| 用户接收确认 | 输入和必要的运行/请求身份已持久提交；请求 ID 可幂等重试 |
| 工具/审批/外部副作用之前 | 必要意图或授权已提交；保存失败使整个运行停止后续副作用 |
| 已显示、尚未提交 | 崩溃可丢未提交尾部，恢复已提交前缀并标明中断 |
| 正文提交但 ACK 丢失 | 相同数据重试不重复追加，冲突重试明确失败 |
| 终态确认 | 完整必要正文、终态条目、完成事件及水位具备一致的提交依据 |
| 工具执行结果未知 | 不自动重做外部副作用，不承诺通用 exactly-once |

结束仍只封闭当前内容块和提交终态，不访问/重编码旧上下文，不做全轮快照或正文回填。

## 8. 预算、调度与读取

| 项目 | 保留的基线 |
|---|---|
| 新格式提交调度 | 约 25 ms，128 事件或 64 KiB；按最老待提交数据计算期限 |
| 正文段/写入/原始读页 | 16 KiB / 64 KiB / 256 KiB |
| 待提交容量 | 每会话 32 MiB、全局 128 MiB，年龄阈值 2 秒；控制准入独立 |
| SQLite | WAL + FULL；专用 writer；有界 query-only reader；独立 PASSIVE checkpoint |
| 客户端 | 保留有界原生传输、分时大 JSON 解码、代次取消和已解码对象传递 |

这些调度值不是最大丢失窗口或任意磁盘下的时延保证。不得降低同步级别、延长落盘间隔、无限排队或阻塞取消来获得空间数字。

分页先读取有界紧凑行，再批量取本页去重后的上下文和扩展字段。查询次数与页数相关，不与事件条数线性增长；解析/组装离开数据库工作线程。
上下文和剩余 JSON 共同计入页/内存预算，不能仅限制变更行而无限加载上下文。
按读取快照捕获身份、代次、epoch 和水位，原子订阅/分页恢复，重叠范围按内容偏移去重；禁止跨 epoch 或历史重写代次拼接。

索引支持流内游标、上下文/消息/工具定位、计费和正文回收。M1 提供实际查询及 EXPLAIN 证据，移除目标新布局不再使用的 JSON 长键索引。
发布过的 legacy 查询仍需相应索引；减少索引必须同时证明查找和删除不会退化为历史扫描。

## 9. 共享归属、回收与消费者

上下文/直接范围成为新的正文引用路径，必须一起纳入归属和回收判断。
新上下文发布、变更、正文及其归属原子生效；不能只加外键却让现有 GC 忽略新引用后误删正文。
显式删除引用才排回收，保持有界空闲清理；新布局的反向索引/删除触发器随契约冻结，复用正文的父子视图相互隔离。

逐项接入：消息历史、工具参数/结果、模型输入及 provider 必需内容、全文检索/原文范围、标题/侧栏、fork、reset、context checkpoint、导出、附件、删除/墓碑/outbox、排队回执与备份恢复。
故障时隐藏未发布 fork/操作；恢复只处理必要的未完成运行及明确暂存归属，不扫描完成历史。

Desktop、mobile、TUI、CLI、channels、host 及 remote 共用相同语义；内嵌与独立 Agent 都需验收。
临时模式继续在提示词准入前排空并断开持久化，内存重放有界，不能将易失游标当作已持久化事实。
现有显式 legacy 日志维护命令不在启动/结束时调度，也不能处理格式 2 正文。

## 10. 历史迁移：必须重新测试的矩阵

紧凑布局完成后统一执行下表，并记录新的源提交、结果和故障证据。
这是用户要求的迁移复测，不可用上一版绿色记录替代。

| 来源/故障 | 必须验证 |
|---|---|
| Agent 发布 schema 2、3、4、5、6、7，各自冻结 DDL | 经真实打开/升级入口到目标布局；旧消息、块、事件、已有快照/计费、skills 和元数据保持内容及身份；旧会话继续写 legacy，新会话创建紧凑格式 2 |
| Agent 空库及允许的 skills-only bootstrap | 正确初始化；陌生应用/伪造版本/不支持的开发结构在任何 schema 写入前拒绝 |
| JSONL 和独立事件来源 | 导入、跳过报告、显式重试、重复启动、来源变化、删除墓碑及 GUI 绑定正确；不覆盖成功或已删除身份 |
| Desktop pre-agent、v1.2.1、CLI settings/workspace bootstrap、contract 1–3 | 原发布步骤顺序/校验和不变；无损归档、外键重建、唯一绑定、来源归属、M0 删除范围正确；正式业务和附件归属保留 |
| 非空源与 WAL、升级前快照 | 快照包含已提交 WAL、可校验且不覆盖；快照失败则不开始升级；旧副本仍可读 |
| 迁移事务提交前后异常/kill/磁盘满 | 当前步骤原子，已提交历史步骤保持其原契约；重启可重试，不声称整个多步骤链已回滚 |
| 升级后再次打开及当前结构损坏 | 不重复迁移/清理/备份；缺失权威表、外键、身份或关键索引明确报错，不补空表伪装修复 |
| 升级后的使用 | 历史分页、原文检索、工具详情、模型续问、fork/reset、排队回执、取消/终态、删除及重连实际可用 |
| 协同备份/恢复/中断恢复 | 两库和托管文件一致，身份正确；恢复轮换代次、旧游标失效；verify/resume/rollback 及每个文件切换故障边界通过 |
| 未发布旧候选布局 | 只要求拒绝与原文件保留；不要求可升级，不加入已发布 schema 列表 |

现有锚点：`agent/src/session/database/historical_upgrade_tests.rs`、`agent/tests/fixtures/database/v2.sql` 至 `v7.sql`、legacy_import、`host/src/store/migrations.rs` 与其冻结 fixtures、CLI data 测试。
不得从当前 DDL 改写 user_version 来伪造历史夹具。已有夹具需扩充覆盖真实续问/新旧并存/失败重试，不能只检查版本号或空库创建成功。

## 11. 开发阶段与退出条件

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| M0：保留清理 | 三个废弃缓存表、重复 review 索引和失效代码退役 | 新库不创建；历史迁移重新证明失败可回滚/重试且有效数据保留 |
| M1：冻结新契约 | 本 review、字段矩阵、确切 DDL/码表/唯一性/归属/查询计划/预算和基线负载 | 未发布替换边界明确，全部消费路径和故障边界有验收项 |
| M2：替换未发布布局 | 上下文、紧凑变更、直接范围及扩展链接；更新准入/布局标记与 legacy 分发 | 不增设上一版兼容 codec，旧开发布局 fail-closed，已发布迁移可进入最终布局 |
| M3：写入与提交 | 有界编码缓存、幂等、事务、水位、背压、控制和独立 checkpoint | 新引用/短 ID 不会先于正文发布；提交失败不改变确认语义 |
| M4：全部读者及生命周期 | 批量分页、协议还原、全端、上下文、共享归属、删除/回收和备份 | 无 N+1 或正文副本，字段无损，fork/reset/删除/恢复都覆盖新引用 |
| M5：历史迁移与验证准备 | 更新基于冻结 DDL 的矩阵、故障注入及基准，审计发布版迁移链 | 每个支持来源及失败边界有明确测试，不沿用旧成绩作为通过依据 |
| M6：统一验收与交付 | 实现后统一本地静态/单元/集成/迁移/故障/性能测试；CI 和人工/真机检查 | 未关闭的数据边界问题阻断；报告新旧基线、结果与限制，再交付人工验收 |

M1 冻结后接线，M4/M5 未完成不启用发布候选。实施中不跑测试，允许静态编译；全部完成后统一测试，失败在最终验证阶段修复并复测。
文档任务本身执行 `make check-docs`，不能把它称为运行时或迁移验证。

## 12. 验收门槛与空间记录

- 字段往返：固定码、存在性、null/空值、Unicode、provider 原始串、未知扩展和多字段事实完整还原；每页及重连重叠无重复/缺段。
- 崩溃矩阵：正文/上下文/直接范围/终态/水位事务前后 kill，写锁、磁盘满、writer panic、ACK 丢失、缓存 ID 回滚，已提交前缀和外部副作用承诺一致。
- 迁移矩阵：第 10 节全部重新运行并留结果；升级后同时验证旧会话和新会话，而非只跑新库测试。
- 共享与回收：只剩上下文/直接范围引用、父删子留、reset 退役和暂存恢复均不误删或泄露跨会话内容。
- 性能：同机同版本构建、同一合成负载比较；正文 1/10 MiB、大小工具输出、1/4/16 会话与历史读取并发；包括高复用和上下文频繁变化/未知字段多的最坏情况。
- 分别记录正文/变更/链接/上下文/各索引的 B-tree 页与 payload、数据库和 WAL 峰值、总写入量、CPU/RSS、提交积压/事务/COMMIT p95/p99/max、读取与首段延迟、帧/输入/取消响应和结束耗时。内存原型的页数不代表实际 WAL 写入量。
- 保留上一版性能目标：正常盘提交积压 p99 目标 100 ms；Desktop 增量更新 p95 目标 16.7 ms、mobile 33 ms；首段 p95 相比基线不回退超过 10%；1/10 MiB 固定尾部结束工作量近似不变。门槛在固定 workload/设备中确认，不以提交周期替代测量。
- 不以长提交间隔、降低 FULL、丢字段、丢恢复信息、完成后回收/VACUUM 获得空间收益。空间明显改善时还须证明延迟/WAL 未实质退化；保留原有 3000 行单表约 31 ms 的已知渲染边界，不伪称所有场景都达到一帧。

原始空间调查 B0、上一版两个合成样本 B1a/B1b、真实结构审计 B1c 和内存原型 B2 各自保留。
新实现添加 B3 及新原始输出文件，记录提交、schema/布局、工具链、负载、页大小、WAL/FULL/checkpoint、采样时机、并发干扰、重复次数和统计量。
旧数据不覆盖、不挑选性替换；跨负载、包含 WAL 的文件大小和单表页占用分别解释。
原个人调查只剩约数时明确标注缺失原始字节，不能补造精确值。

M0 清理范围仍仅为 `workspace_files`、`reference_targets`、`object_references` 及其索引，以及重复的 `idx_review_snapshots_run`。
其他看起来多余的历史结构必须有读写和迁移证据，不能因上一版未发布而误删已发布历史来源。
