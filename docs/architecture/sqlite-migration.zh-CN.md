# Agent SQLite 迁移与运维

Agent 的唯一运行时存储为 `~/.future/agent/agent.db`；Desktop 继续使用独立的 `~/.future/app/app.db`。数据库模型见 [ER](../internals/desktop/ER.zh-CN.md#7-agent-sqlite-存储)，用户体验见 [PRODUCT](../internals/desktop/PRODUCT.zh-CN.md)。Agent 与所有客户端必须同步升级，不支持新旧 RPC 混搭。

## 自动导入

TUI 与 Desktop 共用 Agent 的存储升级代码。已发布的 SQLite schema 2、3、4、5、6
均可直接升级到 schema 7，升级前在 `agent/backups/` 保存经校验的快照。
准入按来源版本校验历史结构：schema 2–4 尚无 `run_snapshots`，保全旧库后由迁移建表；
schema 5 及之后必须保有已有快照，缺失权威历史仍明确报错。仅包含技能表的引导数据库
同样保留安装记录和卸载墓碑。回归夹具冻结历史提交中的真实 DDL，不用当前结构改写版本号
冒充旧库。

新版 Agent 在实例锁保护下、对外服务前导入旧 `sessions/*.jsonl` 与所属 `run-events/` 文件。每次启动会重新发现后来恢复的文件，逐会话记录仍阻止重复导入、自动重试跳过项和复活已删除项。每个会话独立事务：成功数据与导入记录一起提交；实质性损坏使整个会话跳过，其他会话继续。只允许可确认的截断尾行保留完整前缀并记录警告；磁盘、SQLite 等全局故障停止启动。

源文件不删除、不更新。导入后只读写 SQLite，没有 JSONL 双写、离线回退或降级。迁移记录独立于会话保留：成功项不重复导入，跳过项不自动重试，已删除项不复活。跳过会话仍可能保留 Desktop 入口，打开时明确失败，不伪造空历史。

## 旧版 Desktop 数据库

`v1.2.4-history-preservation` 在删除旧 GUI 表前，以事务将 `messages`、
`run_events`、`tool_calls`、`tool_outputs` 的全部列复制到只读 `legacy_*` 归档。
带有指向旧表外键的运行、审批和 review 表也先完整归档，再按当前结构重建并恢复索引。
失败时保留原表，不写入迁移完成记录，可安全重试；新安装只记录迁移，不创建空归档。

`legacy_thread_bindings(thread_id, session_id)` 在已发布的绑定去重迁移前保留历史读取映射。
Agent 仍为运行时真源；原消息源缺失或为空时，可读取 GUI 归档中的正文和混合消息附件元数据。
归档恢复一次返回完整历史，不混用 Agent 分页游标。归档不是模型上下文：没有可写 Agent
绑定的恢复对话会拒绝悄悄创建空会话，需恢复原 Agent 数据或回到原始对话继续。

无归档的消息源缺失会明确报错，不伪造空历史。启动目录对账保留缺失源的对话及附件，
防止部分恢复或切换 Agent 数据库被误判为删除；明确删除对话时仍清除对应归档。
已经被旧程序删除的数据需要更早的备份，本次迁移无法重建已删除的字节。

## 托管文件清理

恢复较旧的 app.db 不能授权删除磁盘上较新的文件。未找到存活归属的附件、聊天工作区和
review 目录登记到 `managed_directory_cleanup`，保留原位置及原始内容。
只有明确删除对话或工作区才在同一数据库事务写入清理凭据；物理清理前再次核验共享归属。
删除失败保留凭据供重试。未知目录不会按年龄自动变成可删除数据。

## 检查与显式重试

先停止该用户的 Agent 及可能启动它的客户端；始终遵守每 OS 用户一个 Agent，不通过改 socket/端口启动第二个实例。

```sh
future agent --migrate-sessions
future agent --retry-session-import 会话ID
```

报告只含会话标识、状态、错误来源/行号/受控类别和警告数，不含对话正文。只有 skipped 项可重试；修复来源后显式执行，不覆盖成功项或已删除项。

隔离验证时将 `sessions/` 与同级 `run-events/` 复制到独立目录，使用：

```sh
future agent --migrate-sessions --migration-source /绝对路径/隔离副本/sessions
future agent --retry-session-import 会话ID --migration-source /绝对路径/隔离副本/sessions
```

数据库创建在该 `sessions/` 的父目录。隔离路径不豁免 Agent 实例锁。

## 备份与恢复边界

- 停止 Agent 后备份完整数据库及仍存在的 `-wal` / `-shm`；不要在运行期间仅复制 `agent.db`。
- JSONL 只是导入前快照，不包含后续 SQLite 新对话。重建库不能恢复这些新增数据，不应作为常规排障手段。
- 未发布开发布局不维护升级链；不认识的布局明确拒绝打开，不自动删除或覆盖。正式发布后的 schema 变化必须提供迁移。
- 高频 delta 按 100 ms / 128 条 / 64 KiB 微批提交，语义事件、读取与关闭构成刷盘边界。异常退出可能丢失未提交 delta；100 ms 是调度目标，不是丢失窗口的硬上限。
- `WAL`、`synchronous=FULL` 和事务保护已提交数据；WAL 保留目标不是磁盘占用硬上限，不需要每次启动运行 `VACUUM`。

## 回归要求

自动化夹具完全构造，使用临时目录，不读取个人对话。保留事务回滚、唯一性/冲突、导入幂等/跳过、删除墓碑、fork、运行恢复、工具隔离、分页范围、事件游标和队列故障测试。真机验证涵盖冷打开、首次回复、上翻、工具详情、压缩、异常、重启和重连；单元测试不替代跨平台及 WebView 验收。

## 会话批量删除

`delete_sessions` 每次接收最多 32 个不同会话 ID；`delete_session` 保持兼容，
复用关闭写入后删除的屏障。可删除会话与导入墓碑统一事务提交，忙碌会话返回可重试
结果。每批仅执行一次空间回收（预算 4096 页），不再逐会话回收。页数预算并非耗时
保证，大量空闲页仍可能留待后续删除或启动压缩处理。Desktop 本地事务分批处理，
复用一个 Agent 客户端，逐会话持久化确认及重试结果。

## 数据库准入与升级契约

Desktop 使用 application_id `0x46554150`、user_version `3`。已知旧版 Desktop
布局以及 CLI 先创建的设置/工作区数据库，通过原有发布迁移链接入。
`app_schema_migrations` 记录新契约的校验和；`app_database_identity` 保存数据库身份与恢复代次。
历史迁移标识保持不变。已接入的数据库在服务前校验核心列、外键目标和会话绑定唯一索引，
不再重放历史破坏性清理。行级孤立 run 仍可被发现、对账及终止。

升级非空旧版 Desktop 数据库前，会在 `app/backups/` 发布经校验的 SQLite 快照；
升级受支持的旧版 Agent schema 前，会在 `agent/backups/` 发布快照。
快照包含已提交 WAL 数据，名称唯一，保留原始表，重试不会覆盖上一次快照。
无法创建或校验快照则不开始迁移。这些是两个数据库各自的快照，尚不是协同备份集，
也不包含附件；下文的协同备份命令单独提供完整备份恢复。

Desktop 只在结构校验成功后提交新契约。旧迁移仍保留各自的事务边界：后续步骤失败时，
已经提交的步骤保留并可继续重试，不声称整次升级已经回滚；最初的快照始终保留。
当前版本的历史结构缺失会明确报错，不通过创建空的权威表掩盖损坏。
共享的 CLI 设置/工作区写入口同样拒绝其他应用和较新版本的数据库。

## 离线协同备份与恢复

`future data backup /绝对路径/新备份目录` 同时占住两个实例锁及数据库写入边界，再生成快照。
备份包括两库、托管图片/review/chat 目录、旧 session/event 来源，以及 Agent 的 settings、
models、auth 文件。备份目录必须位于 FutureOS home 之外，只有 SQLite 完整性检查及逐文件
SHA-256 校验通过后才发布，不覆盖已有备份。暂不支持的符号链接或文件类型会使操作明确失败，
不会跟随到外部目录，也不会悄悄跳过。用户自选的外部工作区目录不在备份范围内。
备份含凭据，应按私人数据保存。

`future data verify 目录` 不启动 Agent 即可校验备份。停止所有写入者后，
`future data restore 目录 --yes` 恢复到原数据根目录，保持历史工作目录路径的含义。
工具先暂存并验证替换文件，轮换恢复代次，再用 `.restore-incomplete.json` 阻止正常启动，
然后切换托管文件。包括旧 WAL/SHM 在内的原文件保留在 `.restore-work-<id>/previous/`。

`future data resume` 继续未完成的切换；`future data rollback` 恢复原文件。
每次重命名后进程中断，都可以继续或回滚。只有操作完成后才解除启动屏障；向前恢复还会再次
校验最终文件集。恢复工作目录不会由孤立目录清理自动回收。工具不停止运行中的进程，也不
删除实例锁文件。

## 故障会话终止

用户取消与持久化重试共用故障终态提交入口。同一会话的故障恢复串行执行；
数据库事务先检查已有终态，只有未结算的确切 run 才补写结果。已提交但应答丢失的终态
保持不变。活任务尚未退出时不能补造终态或释放 lease；重试取消不会影响后续的新运行。
`abort_retry` 也会传播持久化恢复失败，不再返回虚假的成功。


## 来源归属、队列回执与派生索引恢复

Agent schema 7 持久保存数据库身份和恢复代次；Desktop 契约 2 记录每个对话的来源。
不同数据库不能静默接管已有对话。完整恢复会轮换恢复代次，旧游标失效，界面替换缓存窗口，
避免拼接两个快照。旧 GUI 归档分页只读显示，恢复匹配的 Agent 来源后才能继续发送。

`session_tombstones` 独立记录原生及导入会话的删除事实，不随 session 行删除。
`get_session_presence` 每批最多 32 个身份，区分存在、已删除、缺失和导入失败。
对账只在已记录的同一数据库明确证明删除时移除镜像；单纯缺失继续保留。

`queued_run_receipts` 在排队 ACK 前提交请求身份和原始输入；正式开始时，与用户消息、
run_started 在同一事务内消费。重启只将未执行输入恢复为历史中的中断/取消结果一次，
不自动执行模型或工具。重复请求仍返回原 run 身份。无法恢复的原始回执保留并报告，
不阻塞其他正常对话。

`history_index_state` 记录派生显示投影版本。事务触发器使部分索引变更失效，
打开数据库发现派生表缺失时使全部索引标记失效。随后按打开的对话分批读取原始记录、
重建显示索引，不重写历史、不重放任务。正常翻页只查询索引标记和选中正文。
会话列表只取首条用户消息、当前会话元数据和最后一次模型切换，另行统计用户条数，
不再为了列表加载每条用户消息。

`future doctor` 从运行中的存储所有者取得 schema、身份和目录统计，报告导入失败、
无法恢复的排队输入和待重建索引。Agent 连接失败会显示未验证，不把空目录当健康。
这是目录诊断，不是完整 SQLite 完整性扫描；离线备份验证执行完整性和文件哈希检查。

## 手工验收

下面这些场景是人守的那一半，自动化的那一半在 CI 里跑（`cargo test -p future-agent`、
桌面与 host 套件）。先用完整测试副本（`FUTURE_HOME` 指向独立目录）验收；旧数据库和附件/会话目录应来自同一份数据集。

| 场景 | 应观察到的结果 |
| --- | --- |
| 首次打开已知旧版 app.db / agent.db，再重启 | 升级前快照保留；历史条数、正文、附件仍可读取，重复启动不重复迁移或导入 |
| 仅有旧 GUI 归档，Agent 原始数据缺失 | 历史分页可读，显示只读恢复提示；发送不创建空的替代历史 |
| 换成不同身份的 Agent 数据库 | 原对话和文件保留，明确提示来源不匹配，不覆盖绑定 |
| 崩溃遗留运行记录，没有 thread 或任务句柄 | 能请求终止；重复终止不生成重复终态，不影响新 run |
| 运行中排队多条输入后异常退出 | 重启后已接受输入仍在，标记中断/取消，不自动执行工具或模型 |
| 清理异常后点击 Force quit | 正常清理优先；独立进程退出看门狗的 25 秒上限不依赖 UI/Agent/SQLite 回应 |
| 完整恢复切换中被中断 | 正常启动被恢复围栏阻止；resume 或 rollback 可继续，旧文件仍保留 |
| 测试副本的派生历史索引缺失 | 打开该对话时重建显示；原始 entries/message_blocks 不被重写 |

完整备份命令要求停止 Desktop、Agent 及其他写入者；它不会代替用户终止现有进程。
当前备份拒绝符号链接及特殊文件，并且完整恢复限定原数据根目录；备份失败会明确报错。
已经被历史版本物理删除的字节，需要从升级前备份或原始 JSONL 等来源恢复。


## 后续故障边界加固

Desktop 契约 3 增加 `agent_delete_sources`。删除线程、工作区或显式重置时，
在本地删除意图中保留已有的 Agent 数据库归属，线程行消失也不会丢失这份证据。
投递前通过同一实例连接核对数据库身份；不匹配或旧意图没有来源证明时，保留待办和
`last_error`，不向当前数据库发送删除。旧版来源不明的删除意图不会被自动认领。
契约 2 到 3 的迁移只补齐能够从现存 `thread_sources` 证明的归属，失败可重试。

历史、正文分片、发送与观察订阅复用完成来源验证的连接。分页来源键同时包含 Agent
实例身份；Agent 重启或恢复后，旧游标需要重新加载。观察器清空旧实例的事件游标及
临时 run 绑定，避免恢复后的低序号事件被跳过。读取会话设置也校验来源，防止异库标题
写回本地；已知异库的停止请求只取消本地 run，不终止其他来源的任务。

正常历史翻页和运行元数据读取使用只读事务；只有派生索引失效时才申请写锁重建。
合并排队输入在启动前失败时，原始输入立即保留为历史中的取消记录；模型和工具不执行，
已提交正式启动的回执不会被这个失败处理覆盖。

新恢复日志为版本 2，记录各原始根目录的确定性摘要；读取旧版版本 1 的未完成日志仍受支持。
续做及回滚前先检查保留区，回滚完成前再次验证原文件集合。缺失或变化会保持启动围栏。
完整备份拒绝未登记的 SQLite WAL/SHM/journal 文件；快照及嵌套目录在发布前同步目录项，
避免只同步文件内容而遗漏文件名的持久化。

补充手工场景：历史读取中重启换库、恢复后事件序号降低、另一个 SQLite 写入者占用写锁、
保留区文件丢失或变更、合并排队输入启动失败、带未登记 sidecar 的备份、旧版恢复日志续做，
以及删除重试遇到不同数据库或未知来源。这些用例在 CI 中执行；本地通过不能代替 CI 矩阵。

### 继续恢复前的完整性检查与后台来源校验

恢复续做在任何新重命名前，按未完成日志定位已经安装和仍在暂存区的每一个替换根，
重新核对文件摘要、SQLite 完整性以及完整目录清单。漏列文件、重复目录或被修改的
替换内容都会保留启动围栏，并在继续移动原文件前报错。回滚只依赖原文件的摘要，
替换区损坏不会阻止原文件完好时的回滚；回滚中再次退出后，`resume` 遵循已持久化的
回滚方向。旧版恢复日志兼容用例现在确实移除 camelCase 的 `originalDigest` 字段。

非零版本的 Desktop 数据库同时核对迁移记录条数、最小/最大版本和每步校验和。
版本头倒退、未来迁移记录或多余记录均在迁移前拒绝，保留历史，不重放旧步骤。

启动后的 run 恢复、RunGone 修复、活动及已结束 run 巡检，以及远程流附着，在同一
Agent 实例连接上先校验已有数据库归属。已知异库不读取运行状态、不恢复本地状态、
不发送故障 abort。压缩、自动标题和远程会话设置入口遵循相同边界。等待会话停止的
5 秒预算覆盖连接、来源验证及所有 RPC；超时不当作停止确认。显式 Force quit 已有的
25 秒独立退出看门狗继续保留，不依赖这些异步步骤完成。

补充验收：清单漏列附件、暂存替换文件损坏后续做/回滚、回滚中再次退出后 resume、
版本头与迁移记录冲突、后台巡检时切到同名 run 的不同数据库，以及状态 RPC 无响应。
上述回归用例只编写和编译，本地不运行单元测试。

远程桥接的正向和反向历史分页同样明确拒绝缺失的正文来源，不再将缺失伪装成成功空页，
也不以空列表覆盖客户端已缓存的历史。已记录的来源归属在远程正文读取前核对；
不存在的会话设置仍可返回空状态，但这一兼容行为不适用于历史正文。
