# 自动升级事务

桌面升级协调器管理一笔可持久化的事务。平台适配器在应用仍可正常使用时准备执行器，只有共享停服屏障成功后才获得明确的安装提交权限。下载签名校验仍然是强制要求。发现新版本与是否允许原位替换分别判断；便携版和受保护目录安装仍提供手动下载入口。

## 协议与恢复

`checking → downloading → verified → preparing → prepared → cleanup → awaiting-exit/installing → awaiting-validation → finished`

版本化 JSON 记录兼容旧更新器。Rust 校验阶段名称并拒绝倒退。进程内标记和操作系统文件锁共同序列化升级；独立执行器在安装期间持有观察者锁。仍然运行的执行器不会被误判为崩溃遗留。

下一次状态查询会把遗留在 `cleanup` 及之前的未完成事务转为 `not-installed`：适配器只有进入提交阶段后才能替换程序文件。替换阶段中断则保留未知结果并阻止再次安装。用户对手动修复的确认只记录为确认，不等于安装成功。

空闲升级在停服前先可逆地预留终端入口，再由 Agent 在登记工作所用的同一互斥锁下比较活动版本并关闭入口。因此，检查后新到达的 CLI 命令或终端会阻止静默中断。用户明确同意中断时，仍走共享停服屏障。取消更新会释放准备好的执行器，不授予安装权限。

`pending-validation` 表示文件替换完成，等待重启。只有编译版本与目标版本一致、且 GUI 启动及 Agent 就绪的进程才能确认升级，确认前执行平台检查。旧进程不能确认新版本。Unix 执行器在替换期间持有现有 Agent 实例锁；其他 Host 抢先启动时，本次升级在修改文件前失败。Windows NSIS 保留现有实例锁租约。

## 用户体验

设置页只显示版本、下载进度和下一步操作。事务编号、程序路径、内部阶段和原始诊断保留在维护记录与日志中；停服后的更新页面也遵循同一规则。
失败时分别引导重试、重启已安全恢复的版本，或下载安装包重新安装。即使检查更新失败，仍可前往官网获取安装包。
原生确认框使用界面当前语言，与前端共享翻译词典。选择稍后更新会记录正常的 `cancelled` 结果，不显示错误。
恢复操作集中在一个页面，不再重复弹出原生错误框。

## 平台适配器

| 平台 | 准备 | 提交及失败处理 |
| --- | --- | --- |
| Windows NSIS | 先启动独立 PowerShell 观察者，检查程序可读性、创建持久备份，再报告就绪。启动前检查 Job 归属，使用显式文件句柄处理无控制台进程的输入输出。 | 持久提交标记和精确的父进程句柄授权在退出后安装。NSIS 检查可执行文件；观察者恢复后对照完整原始快照。保留无法识别的新文件，无法完整验证恢复时要求修复。首次启动确认前保留备份。 |
| macOS app | 在安装目录所在卷解包，校验代码签名、可执行文件身份及有期限的 GUI/CLI 帮助命令探测，落盘候选文件，准备原生辅助进程。受保护目录提供手动安装入口。 | 使用 `renameatx_np(RENAME_SWAP)` 原子交换完整 bundle，安装路径不会暂时消失。交换前失败不修改旧包；持久化结果失败时尝试交换回去。匹配的新进程确认正常启动前保留旧包。 |
| Debian 系 DEB | 一次 `pkexec` 授权准备原生执行器。它创建仅 root 可修改的副本，重新检查 SHA-256，使用编译时内置的更新公钥独立验签，并检查包身份和版本，并执行不安装的 dpkg 检查。 | EOF 取消，COMMIT 授权执行 dpkg。调用者控制的日志和锁路径以调用者的有效身份访问；发布最终结果前永久释放 root 身份。成功退出还需要包处于预期版本且配置完成。包安装失败要求修复，不依赖两个可执行文件的散列推断回滚。没有密码采集和其他认证回退。 |

## 数据与备份边界

恢复程序文件不等于恢复数据库。新进程可能在后续失败前已经开始数据迁移。因此，首次启动失败时保留旧 bundle / Windows 备份和事务证据，不自动使用旧二进制打开可能已迁移的数据。使用平台安装器或包管理器修复。这与尚未启动新版本的替换失败不同：后者可以在验证原始文件完整后安全重启。

macOS 旧包位于 `<安装目录父目录>/.futureos-<操作编号>/candidate.app`。
Windows 备份位于 `<FUTURE_HOME>/app/updates/<操作编号>/program-backup`。
结果和原生诊断位于操作目录或 `app/logs/update-recovery.log`。未知结果保留恢复证据。

## 验收

本地仅做编译、类型检查、lint 和格式检查。单元与原生夹具交给 CI：

- Agent 工作登记版本竞争与终端入口的可逆预留。
- 准备中断、非法阶段倒退和绑定目标版本的首次启动确认。
- 准备好的执行器取消及明确提交，不执行真实程序安装。
- macOS 原子交换、逆向交换和失败后原目录保持完整。
- Windows NSIS 安装前检查、观察者、完整备份恢复与恢复不完整。
- Linux 已授权的原生执行器和一次性 DEB：EOF 取消、Agent 锁冲突、安装成功等待确认、配置失败。脚本拒绝在 CI 之外执行，使用嵌入测试构建的临时 CI 身份签署夹具，结束时只清理夹具包。

签名 macOS 自动更新产物验证是发布门禁。这些夹具不替代 Windows / macOS 真实签名旧版本到新版本的升级验收、Linux 图形授权代理覆盖和数据库迁移兼容性验收。静态检查不代表这些真实安装路径已通过。
