# 西湖大学 HPC 校园版 FutureOS 接入使用手册
> 面向对象：西湖大学师生（FutureOS 校园版用户）与 HPC 管理老师
> 校园模型门户：<https://hpc.westlake.edu.cn/#/ai-campus>
> 文档版本：v1.4（2026-10-21，新增第三章「远程控制」）

FutureOS 已接入学校 HPC 模型服务。师生可以在两个环境使用：

| 使用方式 | 适用场景 | 运行位置 |
|---|---|---|
| **桌面端（GUI）** | 日常科研助手：对话、写代码、读文献、做 PPT、分析数据 | 自己的电脑（Windows / macOS），通过校园网访问学校模型网关 |
| **终端版（TUI）** | 在 HPC 服务器上直接使用：配合课题代码、数据、作业脚本工作 | 登录 HPC 登录节点（SSH 终端内） |

两种方式的模型配置相互独立（桌面端配置存在个人电脑上，TUI 配置存在服务器账号目录下），可按需只配其一，也可都配。

> **开始前的准备（所有用户）：**
> 1. 确认已接入**校园网**（或学校 VPN）。
> 2. 访问 HPC 门户 AI Campus 页面，按页面指引**申请模型使用权限与 API Key（令牌）**。

## 一、桌面端接入（Windows / macOS）

### 1.1 下载与安装

从 FutureOS 官网下载页获取安装包：

> **下载地址：<https://future-os.cn/download>**

> 📷 **截图位 1-1**：FutureOS 官网下载页（按系统选择安装包）

| 系统 | 安装包 | 安装方式 |
|---|---|---|
| Windows | 安装版 `.exe` | 双击运行，按安装向导提示完成即可 |
| macOS | `.dmg` | 打开后把 FutureOS 拖入「应用程序」文件夹 |

### 1.2 首次启动：先登录账号（推荐），再配置学校模型

首次启动会出现欢迎页，提供两个入口：

**推荐做法：点「登录 / 注册」，先连接 FutureOS 账号。**

1. 在欢迎页点击 **「登录 / 注册」**，浏览器会自动打开授权页面。
2. 完成授权后，应用自动完成初始化（加载模型、安装内置技能）。

> 📷 **截图位 1-2**：首次启动欢迎页（「登录 / 注册」入口）

> **为什么建议登录？** 登录后可以使用官方后台提供的 **100+ 科研技能**（文献调研、数据绘图、PPT 生成等）。如果跳过注册、只配置学校提供商，则**仅能进行模型对话**，无法使用这些技能。

登录完成后，再按下一节添加学校模型提供商，把对话模型切换为学校 HPC 提供的模型。

### 1.3 添加学校模型提供商（核心步骤）

从主界面左下角 **齿轮图标** 进入 **设置 → 提供商**，在「自定义」区域点击 **「+ 添加自定义提供商」**，逐项填写：

| 字段 | 填写内容 | 本服务填写值 |
|---|---|---|
| **名称**（可选） | 显示用的名字，只能包含字母、数字、空格和 `_.()-` | `westlakehpc` |
| **提供商 ID** | 唯一标识，只能含小写字母、数字、`-`、`_` | `westlakehpc` |
| **API 类型** | 选择 **OpenAI Completions** | `OpenAI Completions` |
| **Base URL** | 学校模型网关地址（见下方「网关地址说明」） | `https://hpc-api.westlake.edu.cn/v1` |

**网关地址说明（以 HPC 官网公布为准）**：

| 适用范围 | Base URL |
|---|---|
| 校园网（通用） | `https://hpc-api.westlake.edu.cn/v1` |
| 科学工程计算集群（内网直连，更快） | `http://192.168.103.211:30530/v1` 或 `http://192.168.103.207:30530/v1` |

> 个人电脑（桌面端）用校园网域名版；在 HPC 集群上（TUI）用集群内网 IP 版。若某一地址超时 / 404，换另一个即可。
| **API Key** | 你在门户申请的令牌 | `sk-xxxxxxxx`（个人令牌） |
| **模型** | 点「+ 添加模型」，逐个填入模型 ID 与显示名称 | 见下表 |

**可添加的模型（模型 ID 必须完全一致，区分大小写）：**

| 模型 ID | 显示名称 | 模态 | 上下文长度 | 最大输出 |
|---|---|---|---|---|
| `glm-flash` | GLM-5.3-Flash | 文本 + 图片 | 1,048,576 | 393,216 |
| `Qwen` | Qwen 3.8 | 文本 + 图片 | 1,048,576 | 393,216 |
| `deepseek` | DeepSeek V4 Flash | 文本 | 1,048,576 | 393,216 |
| `deepseek_pro` | DeepSeek V4 Pro | 文本 | 1,048,576 | 393,216 |

> 📷 **截图位 1-3**：设置 → 提供商 → 添加自定义提供商（填写示例）

提供商信息会写入本机的 `~/.future/agent/models.json`，密钥保存在 `~/.future/agent/auth.json`；保存后**新会话立即生效**（如模型列表未刷新，重启一次 FutureOS 即可）。

### 1.4 启用模型并开始对话

1. 进入 **设置 → 模型**，确认 `westlakehpc` 提供商下的模型已出现；不需要的模型可在此隐藏，让列表只保留常用模型。

> 📷 **截图位 1-4**：设置 → 模型（勾选 / 隐藏模型）

2. 回到主界面，点 **New Chat**（快速问答）或 **Workspace**（绑定一个本地文件夹做真实项目）。
3. 在输入框旁的**模型选择器**里选中学校模型（如 GLM-5.3-Flash），输入问题即可。
4. agent 读写文件、执行命令前会**请求批准**（默认"手动批准"模式），确认无误后再放行。

### 1.5 验证配置是否成功

任选其一：

- 在对话框里发一条消息，能正常流式返回即成功。
- 用安装包自带的命令行工具（Windows 在 FutureOS 安装目录、macOS 在 `FutureOS.app/Contents/MacOS/` 内）执行：

```bash
future models        # 列出 agent 已加载的模型，应能看到 westlakehpc 下的模型
future doctor        # 一次性体检：配置、连通性、provider/模型
```

## 二、终端版（TUI）接入（HPC 登录节点）

TUI 面向在 HPC 服务器上工作的用户，在登录节点的终端里运行 `future` 命令即可，**无需图形界面**。以下配置已在 HPC 登录节点实测可用。

### 2.0 登录 HPC（校园版共享账号）

校园版使用 HPC 统一分配的**共享账号**（用户名与密码由 HPC 老师下发，非个人账号、无需 FreeOTP 动态码）。macOS 与 Windows 登录方式相同，都用自带的 SSH 客户端：

| 步骤 | macOS | Windows |
|---|---|---|
| 1. 打开终端 | 自带的「终端 Terminal」 | PowerShell 或 Windows Terminal（推荐，跑 TUI 显示更好） |
| 2. 输入登录命令 | `ssh <你的账号>@172.16.78.132 -p 10004` | 同左 |
| 3. 首次指纹确认 | 输入 `yes` 回车 | 同左 |
| 4. 输入密码 | 输入 HPC 下发的密码，**盲输不显示**，回车 | 同左 |

- 需先接入**校园网**或学校 VPN（`172.16.x.x` 是校内地址，校外直连不通）。
- 登录成功会出现 `[<你的账号>@login04 ~]$` 提示符。
- 不习惯命令行的 Windows 用户可用 MobaXterm / Xshell：主机 `172.16.78.132`、端口 `10004`、用户名填 HPC 下发的账号。⚠️ 共享账号也**不要在客户端里保存密码后自动重连**，避免频繁失败被判定为攻击。

> 端口 `10004` 为当前校园版验证可用端口；如 HPC 后续迁移到 `10011` / `10005`，以 HPC 老师通知为准。

### 2.1 安装

登录 HPC 后，在终端执行**校园版专用安装脚本**（安装到个人目录，无需管理员权限，其他同学共用登录节点也不互相影响）：

```bash
curl -fsSL https://futureos.oss-cn-hangzhou.aliyuncs.com/orgs/westlakehpc/install.sh | bash
```

> 安装脚本会自动完成：

1. 安装 `futureos` 与 `future` 命令（含桌面端组件与 CLI/TUI）；
2. 自动安装 **westlake-hpc 技能**（HPC 相关任务时自动加载）；
3. **询问是否加载 westlakehpc 模型**：
   - 输入 `Y` → 按提示粘贴你申请的 **API Key**，即可一键载入全部学校模型；
   - 输入 `N` → 不加载学校模型（仅可对话官方模型）；后续想配置，见 2.2「手动补配学校模型」。

安装后**还需配置环境变量让 `future` 命令生效**：

```bash
echo 'export PATH="$HOME/.local/bin:$HOME/.future/bin:$PATH"' >> ~/.bash_profile
source ~/.bash_profile
```



### 2.2 手动补配学校模型（安装时选了 N 的用户）

选了 `Y` 的用户模型已一键载入，跳过本节；选了 `N` 或想改模型列表的用户，编辑 `~/.future/agent/` 下的两个文件（目录不存在先创建：`mkdir -p ~/.future/agent`）。

**① 编辑 `~/.future/agent/auth.json`**，写入你的 API Key：

```json
{
  "westlakehpc": {
    "type": "api_key",
    "key": "<YOUR API KEY>"
  }
}
```

**② 编辑 `~/.future/agent/models.json`**，写入学校提供商与模型列表（TUI 跑在集群上，Base URL 用集群内网地址；以下内容可直接复制，只需确认①中的 Key 已填好；如遇个别模型报上下文超限，可把对应 `contextWindow` 调小后重启 agent）：

```json
{
  "providers": {
    "westlakehpc": {
      "name": "westlakehpc",
      "api": "openai-completions",
      "baseUrl": "http://192.168.103.211:30530/v1",
      "models": [
        {
          "id": "glm-flash",
          "name": "GLM-5.3-Flash",
          "modalities": ["text", "image"],
          "contextWindow": 1048576,
          "maxTokens": 393216
        },
        {
          "id": "Qwen",
          "name": "Qwen 3.8",
          "modalities": ["text", "image"],
          "contextWindow": 1048576,
          "maxTokens": 393216
        },
        {
          "id": "deepseek",
          "name": "DeepSeek V4 Flash",
          "modalities": ["text"],
          "contextWindow": 1048576,
          "maxTokens": 393216
        }
      ]
    }
  }
}
```

> 模型列表以 HPC 门户 AI Campus 页面为准；已下架模型（如 `deepseek_pro`）请从列表中移除。

**③ 保护密钥权限（建议执行）：**

```bash
chmod 600 ~/.future/agent/auth.json ~/.future/agent/models.json
```

**④ 验证：**

```bash
future models        # 应列出 westlakehpc 下的模型
```

> 修改 `models.json` 后需重启 agent 才生效（退出 TUI → 杀掉旧 agent → 重新启动，见 2.4）。

### 2.3 登录 FutureOS 账号（解锁官方技能，建议在首次启动 TUI 前完成）

westlake-hpc 技能随安装自动装好；但官方 100+ 科研技能（文献调研、PPT、深度调研等）需要**登录 FutureOS 账号**才可用——不登录只能进行模型对话，技能列表为空。建议在首次启动 TUI 前先完成本节，之后 TUI 里即可直接使用全部技能。

**在普通终端（非 TUI 内）执行**：

```bash
future auth login
```

按提示操作：终端输出授权 URL 与设备码 → 在个人电脑浏览器打开 URL → 注册/登录 FutureOS 账号 → 输入设备码授权 → 终端自动保存（显示 `Saved Future API key`）。验证：`future auth status`。

> 该登录只写入 auth.json 的 `future` 段，不影响学校模型（westlakehpc）的配置；登录后需重启 agent 才读到新凭证（首次配置流程中 agent 尚未启动，无需额外操作）。

**退出（登出）FutureOS 账号**：TUI 内无登出命令，需退出 TUI 后在普通终端执行：

```bash
future auth logout      # 只删除 future 平台密钥，学校模型（westlakehpc）的 Key 不受影响
future auth status      # 验证：应显示未登录
```

> 登出后需重启 agent（见 2.4）才在会话中生效，技能列表回到未登录状态；之后想重新登录，再执行 `future auth login` 即可。

---

### 2.4 启动

安装并配置好后，直接启动 TUI：

```bash
future tui
```

- **无需手动启动 agent**：TUI 会自动探测并拉起 agent sidecar（v1.1.7 起）；SSH 断开后 TUI 与 sidecar 一起退出，会话已保存在磁盘上，重新进入后用 `/sessions` 找回。
- **agent 在跑但 TUI 连不上**（报 `no sidecar could be started`）：单实例锁被占（共享家目录，其他节点/标签页的 agent 还活着）→ 先把其它 TUI 退出，或杀掉旧 agent：

```bash
ps -u $USER -o pid,cmd | grep "future agent"   # 找到 PID（注意带空格的模式）
kill <PID>
future tui                                       # 重新进入
```

- **验证**：TUI 里 `/model` 打开模型选择器应能看到学校模型；也可执行 `future models` 或 `future doctor` 检查。
- 修改配置文件（`models.json` / `auth.json`）后需重启 agent 才生效：退出 TUI → 杀掉旧 agent → 重新 `future tui`。

### 2.5 登录节点 vs 计算节点（重要）

**登录节点支持联网**，计算节点不连外网。两类节点分工如下：

| 场景 | 在哪做 |
|---|---|
| 轻量使用：对话、读文档、写报告、编辑代码、传数据 | **登录节点**（`future tui` 直接用） |
| agent 使用联网技能（网页搜索、下载等） | **登录节点**（计算节点不联网，技能会失败） |
| 安装软件 / conda 环境 / pip 包 | **登录节点**（计算节点无法下载） |
| agent 跑计算型任务（跑脚本、批处理数据、长任务） | **计算节点**（登录节点限 2 核 / 10G，重计算会被 kill 甚至停用账号） |
| 大量数据的计算任务 | **计算节点**（通过 Slurm 申请资源） |

**计算节点上使用 FutureOS 的完整流程：**

```bash
# ① 申请计算节点（在登录节点执行）
srun --mem=8G --pty bash          # 提示符变成 bash-4.4$ 即已进入

# ② 直接启动（agent 由 TUI 自动拉起，无需手动启动、无需带地址）
future tui

# ③ TUI 内切换到项目目录后开始工作
# /cwd /storage/<课题组>/<用户名>/<项目名>
```

分析完成后记得收尾：退出 TUI（`Ctrl+c`）→ `exit` 退出计算节点（Slurm 资源即释放）。

> 若在计算节点上启动报连接错误，可能是旧版本的临时限制（早前版本需 `setsid` 手动拉起 agent 并给 TUI 带地址），升级到最新版即可：重跑安装脚本覆盖更新。

### 2.6 TUI 常用命令速查

**斜杠命令**（在输入框输入，`tab` 可自动补全）：

| 命令 | 作用 |
|---|---|
| `/model [名称]` | 选择 / 切换模型；不带参数打开模型选择器 |
| `/new` | 新建会话 |
| `/sessions` | 浏览、切换历史会话 |
| `/name <名称>` | 给当前会话命名，便于日后查找 |
| `/clone` | 克隆当前会话（在新分支上继续） |
| `/fork` | 从选中的消息分叉出新会话 |
| `/tree` | 查看会话分叉树（fork/clone 层级） |
| `/cwd <目录>` | 切换 agent 的工作目录（如切到课题代码目录） |
| `/status` | 查看当前模型、token 用量、成本 |
| `/compact` | 对话过长时压缩上下文 |
| `/scoped-models` | 配置模型启用 / 禁用列表 |
| `/stop` | 停止当前生成 |
| `/cancel <run-id>` | 取消排队中的运行 |
| `/approve <id>` | 批准待执行的工具操作 |
| `/reject <id>` | 拒绝待执行的工具操作 |
| `/reload` | 重新加载技能与上下文文件 |
| `/help` | 显示帮助浮层 |

**快捷键：**

| 按键 | 作用 |
|---|---|
| `Ctrl+p` | 循环切换模型（也可 `Shift+Tab` 循环思考级别） |
| `Ctrl+t` | 切换思考级别 |
| `Ctrl+o` | 展开 / 收起思考内容 |
| `Ctrl+r` | 浏览会话 |
| `tab` | 触发 / 确认自动补全 |
| `Ctrl+↑` / `Ctrl+↓` | 滚动聊天区（逐行） |
| `PageUp` / `PageDown` | 滚动聊天区（翻页） |
| `↑` / `↓` | 输入框内移动光标；在首 / 末行时翻看历史输入；在弹窗列表（模型、会话）里导航 |
| `Ctrl+c` | 中断当前生成；空闲时再按退出 TUI |
| `escape` | 关闭弹窗 / 收起自动补全 / 清空输入 |
| `Ctrl+l` | 清屏重绘 |
| `Ctrl+w` / `Alt+Backspace` | 删除一个单词 |

**TUI 之外常用的 `future` 命令**（在普通终端执行）：

| 命令 | 作用 |
|---|---|
| `future agent` | 启动后台 agent 服务（TUI 前必须先启动） |
| `future tui` | 启动终端界面 |
| `future run "问题"` | 不进 TUI，一次性提问并打印回答（可配 `--model`、`@文件`） |
| `future models` | 列出已配置的模型 |
| `future doctor` | 一次性体检：配置、连通性、provider/模型 |
| `future session list` | 查看历史会话列表 |
| `future auth login` | 登录 FutureOS 账号（解锁官方技能） |

> 使用建议：agent 执行写文件、跑命令等操作前会请求批准（用 `/approve` / `/reject` 处理）；在 HPC 上请留意它要执行的命令，避免误操作共享存储上的数据。长时间运行的任务建议放在 `tmux` 中。

## 三、远程控制：用手机 / 另一台电脑操作你的 FutureOS

除了在装了 FutureOS 的那台机器上直接用，还可以把桌面端“交给”手机或另一台电脑远程控制：
在人不在电脑前的时候查看回复、发消息、回应审批，会话仍原样跑在原来的机器上。
HPC 场景下最常用的两个方式：

| 远程方式 | 被控的机器 | 适合场景 |
|---|---|---|
| **手机远程**（FutureOS App，Android / iOS） | 自己的电脑（装了桌面端的 Windows / macOS） | 人离开工位时盯任务、回消息、批审批；电脑上的会话照常跑 |
| **桌面远程**（另一台电脑的桌面端 / 主机模式） | 办公室电脑、组内服务器 | 从宿舍或家中访问实验室电脑上的会话；在服务器上开一个不依赖图形界面的入口 |

工具始终在**被控的那台机器**上执行，手机 / 远程端只是查看与操作；所以被控机器要保持开机、
FutureOS 桌面端在运行，并且两端都联网。

### 3.1 手机远程控制桌面端

1. 在手机上安装 FutureOS App（Android 安装包，或 iOS TestFlight 邀请）。
2. 在电脑的桌面端登录，打开左栏 **「远程」** 页，打开 **「远程桌面」** 总开关。
3. 点 **「添加设备」**，浮窗显示二维码与配对码（五分钟内有效、只能用一次）。
4. 手机 App 扫码完成配对（没有相机也可以手动粘贴配对码）。
5. 在手机上即可查看 / 继续电脑上已有的会话，或新建会话：发消息、传附件、切换模型、
   回应审批请求、置顶 / 删除会话都可以；电脑休眠或断网时无法执行新任务，恢复后会自动重连。

> 安全：配对成功后手机与电脑之间端到端加密；配对码不要截图外传。手机丢失或转交他人时，
> 在电脑的「远程」页对该设备 **解除配对**，即可撤销其访问。

### 3.2 从另一台电脑远程控制（含服务器主机模式）

另一台电脑装上桌面端并配对后，同样可以查看 / 操作被控机器上的会话，操作方式与手机一致。

对 HPC 用户还有一类特殊场景：**在服务器上开一个无图形界面的远程入口**（主机模式），
不用 X11 转发、不开桌面，手机 / 另一台电脑照样能连上来操作这个服务器上的会话：

```bash
# 在 HPC 登录节点（建议放在 tmux 里，断开 SSH 后会话不中断）
tmux new -s future-remote
future host
```

- 首次运行会依次打印：登录授权二维码（未登录时）→ 配对二维码（未配对时），
  用手机 App 扫码即可；已完成的登录与配对会复用，下次启动直接进入服务状态。
- `Ctrl+C` 退出；SSH 断开本身不保证进程存活，长驻使用请放在 `tmux` 中。
- 主机模式与图形版桌面端共用同一套数据（`~/.future/`），手机远程控制它的方式完全相同。
  完整步骤与选项见 [主机模式使用指南](guide/desktop-host.zh-CN.md)。
- 也可以在终端直接管理设备：`future remote devices`（列出 / 配对 / 解绑 / 指定在控设备）。

> 适用建议：日常科研助手（对话、写代码、读文献）仍推荐第一章的桌面端；主机模式是给
> “服务器上长跑的会话，人却不在服务器前”的补充用法，二者共用同一份配置与数据。

### 3.3 配置与数据的关系

- 桌面端装在**个人电脑**，TUI 跑在 **HPC 登录节点**，两者的配置互不影响，可只配其一。
- 两者共用同一套配置文件（`~/.future/agent/` 下的 `models.json` 与 `auth.json`）：桌面端在“设置 → 提供商”里填写的内容，最终也写进这两个文件。因此桌面端照第二章同样的参数在界面里填写即可。
- 远程控制不改变这一关系：手机 / 远程端操作的是**被控机器上已配置好的**会话与模型，
  不需要在手机上再配一遍学校模型。
- 个人数据位置：个人电脑与服务器上均为 `~/.future/`（Windows 为 `C:\Users\<用户名>\.future`），会话记录、密钥都保存在本机。

## 四、常见问题（FAQ）

| 症状 | 原因与解决 |
|---|---|
| 桌面端 / TUI 报连接或 gRPC 错误 | agent 没在运行。桌面端：重启 FutureOS（会自动拉起后台服务）；TUI：先跑 `future agent` 再开 `future tui`。 |
| 提示 "no model" 或 auth 错误 | 未配置模型或密钥。检查 `models.json` 的 `baseUrl`、模型 ID 是否与本文一致，`auth.json` 的 Key 是否正确。 |
| 请求 401 / 鉴权失败 | API Key 错误或已过期，回门户重新获取并更新 `auth.json`。 |
| 请求 404 / 超时 | Base URL 不对（见 2.2「网关地址说明」：校园网用 `https://hpc-api.westlake.edu.cn/v1`，集群上用 `http://192.168.103.211:30530/v1`），或当前网络不通校园网 / VPN。 |
| 模型列表里看不到刚加的模型 | 桌面端：保存后新会话生效，必要时重启应用；TUI：重启 `future agent`。 |
| TUI / 桌面端可以对话，但用不了技能 | 未登录 FutureOS 账号。见 1.2：登录后技能才可用（桌面端登录；TUI 可用 `future auth login` 登录）。 |
| 手机扫码后连不上 / 配对码无效 | 确认电脑上「远程」页的总开关已打开、配对码未过期且生产 / 测试版本匹配；无相机可手动粘贴配对码。更多见 3.1 与第三章。 |
| 主机模式启动报错或 SSH 断开后进程没了 | 见 3.2：长驻使用请把 `future host` 放在 `tmux` 中；SSH 断开本身不保证进程存活。 |
