不是设计文档，是一次落地的记录：把一个只存在于本地分支上的提交——`8958cf069`，
`wip(tui): preserve the file-mention and permission work left uncommitted here`——里

## 2. 哪些没落，以及为什么

### 2.1 `/models` 模型范围面板——一个没有读者的完整控件

快照加了 `PickerKind::Scope`、picker 上的 `marked` 集合、`space` 勾选、
`SetModelScope`，还把集合存进 `settings.enabledModelIds`——然后就没了：范围的唯一用途
是限定**某个按键轮换哪些模型**，而那个按键是 `ctrl+p`（第 9 项），在当前界面上已经归
命令面板。打开这个面板，屏幕上会多出一个菜单，唯一效果是一个没人读的偏好——正是"半截"。

### 2.2 `/permission` 面板——已经有两条路了

`live.rs` 里已经有 `set_permission_level`、`cycle_permission`（启动台权限 chip 与
`/permission <level>`）以及 `all → workspace → none` 的阶梯。给同样三个值再加一个面板，
是给已经有两条路的值修第三条，而且它的行还得重新写成 i18n 键才画得出来。没有新能力。

### 2.3 状态栏三段可点

这项改动有三分之二指向它想打开的面板（`status.model`/`status.effort` → 模型面板，
`status.permission` → §2.2 那个不落的权限面板）。另外那行在窄终端上会被 `fit()` 截断，
所以某一段的矩形可能落在已画文字之外——一个盖在空格子上的点击目标。不落：它需要一次
独占的窄终端处理，而它的权限段没有面板可开。

### 2.4 帧去重、`?2026`、tick 派发——已经被另一种方式解决

快照的 `previous_frame` 缓存回答的是"字节有没有变"；驱动循环现在用 `TickClock` 正式
回答这个问题（见 `tui-event-loop-cost`）。`?2026`（同步刷新）是快照顺手夹带的**另一个**
缺陷：没有测试、与提及无关，属于循环成本那条线，不该塞进提及菜单的移植里。tick 派发只
是为了"粘贴之后打开 `@` 菜单"；现在菜单在合成帧时同步，根本不需要 tick。

### 2.5 粘贴进 overlay 的查询行

是个真缺陷，但快照的版本只覆盖了界面上八个 overlay 里的两个（面板、picker）——当前还有
偏好、键位、队列、审批、diff、历史、树、fork、worktree。落一个 2/8 的修法会让人以为
"粘贴已经好了"，而它并没有。记在这里，作为需要单独一轮的缺陷。

### 2.6 侧栏默认页签

`panel: PanelId::Sessions` 是偏好不是功能，而且当前默认行为有测试断言侧栏就开在待办上。
这不是一次移植，是另一个产品决定，也不该由这份记录替它做。

## 3. 键位冲突（第 9 项出局的原因）

| 按键 | 快照想干的事 | 界面已经占着的 | 处置 |
|---|---|---|---|
| `ctrl+p` | 轮换到下一个模型 | `preferences::Action::Palette`——**可改绑**的动作，`/preferences` 里看得见 | 现有为准；换模型留在 `/model` |
| `ctrl+r` | 打开会话面板 | `preferences::Action::Sessions`——已经是同一件事 | 无需移植 |
| `ctrl+t` | 轮换推理强度 | 空着，但它唯一的用途是模型范围（§2.1） | 不落 |
| `ctrl+y` | 轮换权限等级 | 草稿编辑器的 `ctrl+y`（yank） | 现有为准 |
| `ctrl+m` | 打开模型面板 | 空着，但在很多终端上与 `Enter`/`ctrl+enter` 同码 | 不落 |

这份记录落地的 `@` / `#` / `/` 都不占全局键：`@` 和 `#` 是**草稿里的 token**（以信号符
开头的 token 打开菜单，其它键照常编辑草稿），`/` 本来就已经是命令面板的键。

## 4. 最难的两处冲突，取了哪边

**A. `palette_entries()` 是 `(command, description)` 二元组，快照要一个行类型。**
当前面板的说明文字来自 i18n 表，并且给每一行已画的行注册一个命中区，行号等于它的绘制行号。
加入技能会插入一行**分组标题**，恰好破坏这个等式。处置：取当前结构
（`Vec<(&str, Key)>` + `t(lang, key)` + 逐行注册），在上面加行类型——
`PaletteRow::{Command,Skill}`，在种类切换处各打一次标题，并在**同一个**绘制循环里推进
命中区的行计数器，这样标题出现后点击也不会错一行。没有采用快照里另起一个 `paint` 循环的
写法：两个必须彼此吻合的循环，正是当前代码在避免的那个 bug。

**B. 草稿是 `EditorState`，不是 `InputView { text, cursor }`。**
快照里每一处提及编辑都是对普通字符串的一对字节偏移，而且它自己的 `WbAction::FillDraft`
在当前界面上不存在。处置：保留当前编辑器，把插入与面板补全都用已有的
`WbAction::EditInput { text, cursor }` 表达，由 `Live::set_draft` 经 `EditorState::set`
落地。没有采用的是快照把菜单同步放在 tick 处理器里这一点：现在菜单在 `handle()` **和**
`render()` 里都重新推导，因而不依赖 tick 到来——这也顺带免掉了第 12 项里的循环改动。

两处是同一条规则：当双方分歧在于新功能要落进去的那个**结构**时，以当前结构为准，把新
功能适配上去；只有属于功能自己的行才照抄。

## 5. 截图：不更新，有理由

快照的两张 PNG 是在**那个 worktree 当时的界面**上渲染的——双语改造之前，侧栏、状态行和
输入框都不同。它们不是这次落地代码的证据，所以删掉，而不是拿另一个构建刷一遍。

试拍过一次并被否掉，理由值得记下来：脚本化截图跑的是 demo agent，它的会话 cwd 是占位的
`/Users/you/future-os`，于是 `@` 菜单在那里**一个候选都没有**，画面写的是"没有匹配"。
这是一个诚实的帧，但不是这个功能的好照片——候选只在会话 cwd 真实存在时才有。实拍的路
是走 harness 的 `--addr`，接一个真实 checkout 里的活会话：

```bash
cargo build -p future-cli --bin future
python3 scripts/screenshots/capture.py --out docs/tui/assets tui mention.png \
  --scenario chat --addr <活 agent 的 addr>   # 然后在画面里敲 `@`
```

因此 `docs/tui/workbench-spec.md` §10 仍然是原来那套图。那张表没有错，只是比这个功能旧。

这份记录唯一抬高的是 `BUDGET`（35 → 37），给 `live.rs` 里两条 `@path` 内联说明

i18n 表该管的界面文案；因此在原地用 `// i18n: prompt text for the model` 标记，而不是
写进白名单。

## 8. 这份记录留下的已知缺口

- **粘贴进 overlay 的查询行**（§2.5）：面板或 picker 打开时，粘贴仍然进草稿。
- **`@` 在 cwd 不存在的会话里没有候选**，这是设计：菜单读的是**会话的**目录。挂在一个
  本机不存在的 cwd 上的会话，看到的是空菜单而不是过期的列表。
- **`ctrl+alt+[` 这类双字节转义**仍由键解析器整段读取；第 5 项的拆分会拒绝猜测，
  拆不开的块照旧当文本。
- **模型范围**在"有一个不叫 `ctrl+p` 的键去轮换模型"之前没有归宿；已存的
  `enabledModelIds` 设置仍然无人读取。
