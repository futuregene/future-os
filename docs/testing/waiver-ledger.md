# Waiver ledger — what is not covered, and under which policy

Generated by `.future/cov100/gen-final-docs.py`. The repo's policy has three
categories, and each waived file must state one on the same line as its path:

* `unreachable-by-construction` — no input reaches it (needs the invariant).
* `unreachable-in-this-environment` — needs a host/fixture this machine cannot
  provide (needs which one).
* `attribution-artifact` — the line is a region llvm-cov attributes to a macro
  or a closing brace (needs the neighbouring covered lines as evidence).
* `platform-unmeasured` — compiles only on another OS; see
  `platform-coverage.md` for the authoritative platform.

The gate checks STRUCTURE only. Whether each reason is true is the reviewer's
job, and rev-rust / rev-fe are tasked to falsify them by counterexample — a
waiver that survives is evidence, a waiver that falls is rework.

## Policy notes

* A file listed under an `OPEN` / `not waived` heading counts as **not waived**
  — the gate rejects it even if its path also appears in a ledger table. That
  rule exists because one delivery relabelled 17 OPEN lines as waived.
* Deleting a production guard so a line stops existing is the forbidden inverse
  of this policy: a coverage change may only ever be a *result*. rev-rust is
  tasked to read `git diff` for removed guards and demand the correctness
  argument for each.
* Weakening an assertion to make a suite green is likewise out of policy; the
  weak-test audit (`weak-test-audit.md`) and the assertion audit cover that.
