# Remote 拆包人工验收

[English](remote-package-manual-acceptance.md)

对应[开发计划](../architecture/remote-package-development.zh-CN.md)第 0～5 阶段。本文是待执行清单，不是通过记录。自动化验收通过后，冻结一个完整 commit；Desktop GUI、headless、匹配的 CLI 和 Mobile 都从该 commit 构建。人工期间如果修改产品源码，重新执行受影响的自动化和人工项目，并重新记录候选。不得把不同版本的结果拼成同一候选通过。

## 候选与环境记录

- 完整 commit、分支、CI URL 与结论：待填。
- GUI/headless 所在系统、架构，Mobile 系统、真机型号和构建渠道：待填。
- 平台/中继环境、既有配对的来源版本、执行人、时间：待填。只记录公开标签，不记录邀请、令牌、密钥或认证 URL。
- 每项记录 PASS / FAIL / 未执行、观察结果、脱敏证据及关联问题。未执行不能视为通过。

在隔离工作目录构建，使用测试账号、专用工作区和无敏感内容的文件。不要覆盖日常数据或停止现有 Agent。既有配对兼容使用专用测试系统用户保存的旧版本数据，升级前备份该测试数据；新配对与兼容升级分别执行。同一数据目录的 GUI/headless 顺序运行。独立 Agent 场景使用独立 FutureOS home 和未占用端点，按现有 Agent 使用指南启动。

源码入口：GUI `make run-desktop`；Android `make run-mobile-android`；iOS `make run-mobile-ios`；headless 与匹配 CLI `make build-desktop-headless`，再在交互终端运行生成的 `futureos-headless`（Windows 使用 `.exe`）。headless 具体登录、配对、退出步骤见[使用指南](../guide/desktop-headless.zh-CN.md)。构建入口不等于本项已通过。

## 操作与预期

| 项目 | 具体操作 | 预期结果 |
|---|---|---|
| GUI 可见启停 | 启动无配对 GUI；启用 Remote，不添加设备；再关闭 Remote | 空机器可显示 Enabled，不自动创建邀请；关闭后不接受远程操作 |
| 新配对 | GUI 添加设备，用 Mobile 扫描或粘贴完整邀请，连接；再次使用同一邀请 | 首次成功，设备身份正确；已消费邀请不能再次完成配对；诊断日志不出现完整邀请或密钥 |
| 既有配对兼容 | 先用旧版配好专用设备，再升级同一测试数据到候选；重启 GUI 与 Mobile | 无需重配，配对簿、主机身份、会话和凭据继续可用；不因升级更换路径或丢失设备 |
| Desktop 主控 | 第二台候选 Desktop 连接第一台；读取目录、打开会话、发送消息，再断开 | Rust 主控与被控正常互通；断开保持断开，不被旧恢复任务重新接回 |
| Mobile 会话与补齐 | Mobile 创建会话，发送会产生流式文本和工具结果的请求；切换会话并加载历史 | 会话、顺序、文本和工具结果正确；本地会话与远端投影不串；历史分页不缺失、不重复 |
| 网络与前后台 | 活动会话中断网，再恢复；分别切换 Wi-Fi/移动网络、锁屏后回前台 | 状态变化可见，恢复后补齐事件与目录；无需重配，不产生重复消息或重复请求执行 |
| 多设备控制权 | 同一被控配两台主控；B 显式接管，再由 A 接管；检查双方界面并尝试写入 | active/standby 与 holder 及时更新；standby 不执行受控业务；切回后目录与事件恢复 |
| 多远端隔离 | 一台主控连接两个有不同标识内容的被控，切换会话；停止其中一台 | 身份、目录、事件、文件不串；一个远端停止不影响另一个；原远端恢复仍属于自身 |
| 审批 | 从远端触发测试环境中确定需要审批的操作，先拒绝再允许 | 宿主展示审批；拒绝不执行，允许只执行对应操作，结果回到正确会话 |
| 沙箱与路径 | 从远端访问允许的测试工作区，再尝试宿主策略明确禁止的路径/操作 | 允许操作正常；禁止操作被原策略拒绝，不因 Server 接口抽离绕过授权 |
| 原生文件 | 上传/下载小文件、大于单块的文件、空文件和含中文/空格的文件名；本地核对大小与摘要；从 Mobile 打开/分享 | 字节与名称正确；选取、保存、打开和分享使用原生宿主流程，无跨设备文件混入 |
| 传输中关闭 | 大文件传输中关闭 Remote，随后等网络/读取恢复；重新开启后再传一个文件 | 原传输失败或取消，不能迟到写入/误报成功；重开后的新传输正常，旧任务不污染新实例 |
| GUI 退出 | 保持远程连接与活动请求，关闭主窗口/退出；等待后从 Mobile 再发请求，再重开 GUI | 关闭即关闭远程入口，等待期间不能接受新操作；重开使用有效原配对，无旧任务复活 |
| headless | GUI 退出后交互启动 headless，按指南登录/配对或复用已有配对；从手机读写，活动中 Ctrl+C；重启 | 不启动窗口；终端显示状态；Ctrl+C 结束入口并回到 shell；重启正常复用有效配对 |
| 外部 Agent 归属 | 在专用环境先启动独立 Agent，再连接 GUI/headless；退出宿主 | 远程入口关闭，原独立 Agent 仍可正常响应本地客户端；不误杀外部进程 |
| 撤销与重新配对 | 移除一个测试设备，尝试用其旧凭据重连；添加新设备；再测离线移除后联网 | 旧设备按既有撤销/刷新规则失效；其他设备保留；待撤销记录最终处理，新配对正常 |
| 凭据刷新与退出竞争 | 在测试平台可控的续期窗口维持两台设备连接；令 standby 槽续期；续期期间关闭宿主 | 正确槽续期，不误用主槽凭据；关闭后迟到结果不重新安装桥或开启入口。不能控制续期时标记未执行 |

## 平台覆盖与结束条件

至少明确记录 Windows、macOS、Linux 宿主，以及 Android/iOS 真机哪些项目已执行。环境缺失的项目逐项保留待确认，不用其他平台的通过代替。TLS/私有 CA、自建中继授权和操作系统差异以相应真实环境验证；独立互通工程的无认证 loopback broker 不能替代它们。

所有失败先给出复现步骤、预期/实际结果和候选，再修复并复验。只有统一自动化证据齐全、必需人工项目由用户确认，才能将整体 Goal 标为完成。性能结论另需开发计划要求的同 runner、工具链、特性和缓存条件下测量，人工通过不能替代性能证据。
