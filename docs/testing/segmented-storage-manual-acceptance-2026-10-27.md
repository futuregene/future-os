## 启动候选版本

使用交付时注明的分支和提交。不要用仍在运行的旧 Agent 验证新客户端：
这次修改了存储 schema 和能力协商，所有参与测试的客户端/服务端应使用候选版本。
先关闭旧开发版，再从仓库启动；先用独立数据根检查崩溃场景。

```bash
FUTURE_HOME=/tmp/future-segmented-manual-20261027 make run-desktop
```

这个路径是整个 FutureOS home，不是 sessions 子目录。首次使用需要在测试实例

Windows 各自入口见 Makefile 的 `run-desktop`。真实历史兼容在后面的独立步骤检查。

## 检查顺序与预期

| 场景 | 操作 | 通过条件 |
|---|---|---|
| 新对话持续输出 | 让模型输出较长正文/思考；输出期间输入、滚动、打开工具详情、切换再切回 | 持续显示，输入/取消可用；不在结束后突然冻结；切回后正文无重复或缺段 |
| 取消与再次发送 | 长输出时取消，等状态稳定后发送新问题 | 已产生内容保留，取消状态明确；下一轮正常开始，没有上一轮尾部串入 |
| 大工具输出与参数 | 让工具在测试工作区产生较大输出，再展开参数/结果 | 详情完整、Unicode 正确；历史和实时结果一致；读取不拖住另一个正在输出的对话 |
| 工具与模型协议字段 | 多轮工具调用；包含推理的模型再继续提问 | 不出现缺失推理/签名/工具结果导致的 provider 拒绝；展示正常 |
| 崩溃恢复（仅隔离实例） | 在输出中途强制结束测试实例/测试 Agent，再使用同一测试数据根重启 | 已提交前缀保留，未完成运行明确标记；允许丢失未提交尾部；不虚报完成、不自动重做结果未知的工具副作用 |
| 完成后重启 | 等一轮显示完成后关闭并重开 | 用户消息、回复、工具结果、完成状态全部保留 |
| 手机/远程重连 | 输出期间断开再连接，切换会话并重新读取详情 | 从正确会话/运行/偏移续读，文本不重复；旧客户端明确提示能力不兼容，不能显示空历史冒充成功 |
| Fork | 从一条用户消息分叉，在父子两边继续对话 | 既有正文正确且独立；重启后仍正确；删除一边不会损坏另一边 |
| Reset 与上下文摘要 | 在测试会话按现有产品流程重置/做模型上下文摘要，再继续 | 选定范围准确；历史检索和模型需要的原文仍符合原有产品语义；没有整轮落库整理导致的结束卡顿 |
| 备份与恢复 | 对隔离实例执行现有数据备份/恢复流程 | schema 8 可验证恢复；恢复后没有错会话、缺正文或串用旧代次缓存 |

## 真实历史兼容

完成隔离实例检查后，按现有备份流程保存数据，再用候选版本打开原有数据根。
检查旧长对话、已有工具结果/附件、已有快照、搜索、继续提问和分叉。旧会话
保持旧格式，不安排历史正文转换或自动压缩；新建会话使用格式 2。

可以只读核实 Agent 库中的 `session_formats` 与既有记录；不要靠数据库文件
立刻变小判断是否成功。已经分配的 SQLite 页/WAL 的复用和 checkpoint 时机
与新写入效率不同。本次不要求也不执行历史 VACUUM/压缩。

主干保留的 `future session journal` 手动回收旧原始日志命令属于显式维护功能，
不属于本次兼容验收步骤；新规范会话会被它跳过，正常启动/结束不调用它。
