# `future tui` 需求与验收说明（全屏 Workbench）

给测试同学用的一页清单：这个界面要满足什么、怎么跑起来、按什么顺序点什么、什么算通过。

- 适用界面：`future tui` 的**全屏工作台**（workbench）。旧的「把行追加到终端 scrollback」的行内界面已删除，不是弃用。
- 文档基于 `main`（2026-10-27，`9e94740`）。**动手前先记版本**：`future --version` 和 `future version --json` 的 `gitCommit`。
- 按键以**界面内 `?` 帮助**为准。`future tui --help` 的按键表比界面落后一版（仍写着 `ctrl+b` 侧栏、`ctrl+k` 刷新），见到不一致按 `?` 的值记，并把 `--help` 的偏差当成 S4 报出来。

---

## 0. 先搞清楚：这次不认识旧界面了

如果你上次测的是 v2.0.1 或更早的 `future tui`，那套「把对话一行行追加进终端、只对末尾做 diff」的行内界面**已被删除**，不是弃用、也没有 `--legacy` 开关。现在 `future tui` 是唯一界面：占满整屏、自己有头部/侧栏/状态栏/提示行，鼠标可点可拖。

另外两处行为变化，直接影响怎么测：

- **不再自己启动 agent。** 旧版找不到 agent 会在后台拉一个 sidecar；现在只连接已经在跑的 agent，没有就报错退出并告诉你去启动哪个（见 §3 A1）。
- **键位整组换过。** 默认规则是「只用 `ctrl`」，没有 `alt`、没有功能键。私下拉过旧习惯的话，`ctrl+d` 现在是侧栏（不是紧凑视图），`ctrl+e` 是折叠过程，`ctrl+k` 是输入框的删到行尾——**刷新走 `/refresh`**。

## 需求清单（验收范围）

界面要满足下面 12 条。每条后面写着验证它的测试组编号，不用另找地方对。

| # | 需求 | 验收要点 | 测哪里 |
|---|---|---|---|
| R1 | 全屏终端界面，是 `future tui` 的唯一界面 | 占满整屏，有头部/对话/输入/活动/状态/提示/侧栏；没有 `--legacy` 或第二个界面 | §3 B |

| R4 | 对话可读、可滚、可翻页 | 流式输出；每次工具调用一行；过程可折叠；往上滚回到阅读位置；到顶自动加载更早一页 | §3 C |
| R5 | 会话可浏览、可切换、可管理 | 侧栏两个页签（最近/工作区）；按顺序上/下切；置顶；删除要确认 | §3 D |
| R6 | 输入框够用 | 多行草稿、完整编辑键、撤销重做、`@` 文件与 `#` 会话补全、草稿按会话保留 | §3 E |
| R7 | 一切设置可在界面里改 | 命令面板、7 个选择器（模型/强度/审批/工作区/主题/会话/语言）、偏好面板、快捷键可重绑 | §3 F |
| R8 | 审批不透明的地方必须说清楚 | 审批卡显示工具/风险/动作路径；允许一次、规则并允许、拒绝；`esc` 不算放弃；多端不卡死 | §3 G |
| R9 | 工作区可看可预览 | 文件面板一层一层读；文本预览、图片走终端图形协议；不支持的终端老实说明 | §3 H |
| R10 | git 与改动只读可查 | `/git` 四视图带泳道图，`/diff` 显示真实 patch；**不提供 stage/commit/checkout** | §3 I |
| R11 | 该提醒时提醒，不该提醒时不打扰 | 本端跑完且失焦才通知；审批与失败总是提醒；别人起的 run 不提醒 | §3 J |
| R12 | 鼠标可用，退出必须还原终端 | 点击/拖拽/滚轮；`/mouse` 可放开原生选择；`ctrl+c` 与信号退出都还原光标、备用屏、鼠标捕获 | §3 J、§3 K |

## 快速冒烟（约 15 分钟）

跑完这 8 条没挂，就可以按 §3 深挖：

1. `future host` 起着的前提下 `future tui` 能进界面（A2）。
2. 发一条消息，看到流式输出、结束后状态栏 ctx 数字有变化（C1）。
3. `ctrl+e` 折叠/展开过程，再按回来（C5）。
4. `ctrl+d` 叫出侧栏，`shift+↑↓` 换一条会话（D1、D6）。
5. `ctrl+p` 打开命令面板，输入 `mode` 回车，选「完全访问」（F1、F5）。
6. `ctrl+f` 打开文件面板，展开一个目录、预览一个文件、`esc` 关掉（H1、H2）。
7. 拖一下侧栏分隔条，滚一下对话（K2、K3）。
8. `ctrl+c` 退出，终端光标和鼠标选择都恢复正常（J6）。

## 1. 准备环境

`future tui` **只连接**已经在跑的 agent，它自己不会启动、也不会重启 agent。所以先让下面任一方式把 agent 跑起来：

| 方式 | 命令 | 说明 |
|---|---|---|
| 前台宿主 | `future host` | 推荐。同一台机器一个数据根只应有一个 agent |
| 桌面端 | 打开 FutureOS 应用 | agent 在桌面进程里 |
| 单独 agent | `future agent` | 最小、最可控，适合测 UI |

然后另开一个终端：

```bash
future tui                 # 打开界面
future tui --continue      # 接着最近活跃的会话
future tui --session <id>  # 指定会话
future tui "第一条消息"     # 打开界面并直接发出第一条消息
future tui -p "只问一句"    # 不进界面，打印结果
```

被测机需要：终端 ≥ 88 列（侧栏才有位置）、≥ 24 行（活动行才显示）、一个可用的模型（`~/.future/agent/models.json`）。

## 2. 界面长什么样

```
 头部（2 行）：会话标题 · 工作区 · 后端状态，下面是细分隔线
 ──────────────────────────────────────────┬──────────────────────
 对话（底部对齐，往上滚有「更早」）          │ 侧栏：最近 | 工作区
                                            │ ▸ 会话标题  future-os · 2m
 输入框（❯ 多行草稿，会随内容变高）          │
 活动行：⠋ 思考 · 3s · 2 工具              42 tok/s · 缓存 96%
 状态栏：模型 · 强度 · 审批模式   ░░ ctx 6.9k/1.0M 0.7% · ≈¥0.01
 提示行：ctrl+d 侧栏 · ctrl+r 会话 · ctrl+p 命令 · ctrl+q 偏好设置 · ctrl+n 新会话 · ? 帮助
```

各区域职责：

| 区域 | 看什么 |
|---|---|
| 头部 | 当前会话名、所在工作区、agent 是否连上 |
| 对话区 | markdown 渲染、工具调用（默认一次调用一行）、思考块、图片链接、失败行 |
| 输入框 | 多行草稿、`[Image #N]` 附件标记、`· 📎 N 张图片` |
| 活动行 | 正在做什么（思考/工具/输出）、耗时、工具数、tok/s、缓存命中 |
| 状态栏 | 模型 · 推理强度 · 审批模式 · 上下文占用条 · 累计费用 |
| 提示行 | 当前生效的快捷键（改键后会跟着变） |
| 侧栏 | **默认收起**。`ctrl+d` 依次 显示+聚焦 → 取消聚焦 → 收起 |

## 3. 测试项

每条记为 `通过 / 失败 / 阻塞`，失败时写清编号和复现步骤。

### A. 启动与连接

| # | 操作 | 预期结果 |
|---|---|---|
| A1 | 没有任何 agent 时执行 `future tui` | 退出码非 0，提示里说明「本数据根没有 agent 在服务」，并给出可执行的办法（`future host` / 桌面端 / `future agent`）。**不会**自己拉起一个 agent |
| A2 | 先跑 `future host`，再 `future tui` | 正常进入界面，头部显示已连接 |
| A3 | 桌面端在跑时开 `future tui` | 同上，两者复用同一个 agent，会话列表一致 |
| A4 | 换一个不兼容的 agent 版本 | 明确报版本/协议不兼容，且不尝试本地启动 |
| A5 | TUI 已进入界面后，Ctrl+C 杀掉 agent | 界面不崩；恢复 agent 后重连可用（可用 `/refresh` 手动刷新） |

### B. 布局与断点

| # | 操作 | 预期结果 |
|---|---|---|
| B1 | 120×38 终端打开界面 | 七个区域齐全，没有多余空行，每行不越界 |
| B2 | 把终端缩到 < 88 列 | 侧栏收起；`ctrl+d` 改为全屏打开当前面板；底部三行提示不截断成半个词 |
| B3 | 把终端缩到 < 24 行 | 头部压成 1 行，输入框只留上边框，活动行隐藏 |
| B4 | 在 1×1 到 200×60 之间拖动窗口 | 不 panic、不出现错位残影（诊断信息写在 `~/.future/tui/debug.log`，需 `PI_DEBUG_REDRAW=1`） |

### C. 对话与滚动

| # | 操作 | 预期结果 |
|---|---|---|
| C1 | 发一条消息 | 先出现活动行（思考/工具/输出），随后正文流式输出；结束后活动行回到 idle |
| C2 | 发一条会调用工具的消息 | 每次调用**只占一行**（如 `read src/main.rs:1-20`、`$ make test`）；`/tool-output` 展开正文（每次最多 200 行，超出提示 `truncated`），再执行一次收起 |
| C3 | 长回答时手动向上滚 | 停在阅读位置，不会被新输出拽回底部；有新输出时出现提醒徽标；`esc` 回到最新 |
| C4 | 在对话顶部继续 `pageUp` | 自动加载更早一页（每页十轮），插在屏幕上方，滚到真实开头时停住 |
| C5 | 按 `ctrl+e` | 「最终输出 / 完整过程」切换：默认把每轮的过程折成一行汇总；这是本次运行的查看开关，重启后回到收起 |
| C6 | 一轮失败 | 失败调用带 `✗`，不铺红底，展开后才看原因；失败行不会被折叠藏掉 |

### D. 侧栏

| # | 操作 | 预期结果 |
|---|---|---|
| D1 | 首次启动 | 侧栏**收起**（对话占满宽度）；`ctrl+d` 叫出来，再按一次收起 |
| D2 | 「最近」页签 | 正在跑的会话单独一组「活跃」（带 spinner），其余在「更早」；两组都有内容时才画标题 |
| D3 | 「工作区」页签 | 依次是「置顶」→「工作区」（每个目录一个标题）→「对话会话」；行的第二行写工作区**名字**而不是长路径 |
| D4 | 侧栏聚焦时按 `p` | 置顶/取消置顶该会话所在工作区，重启后仍在 |

### G. 审批

|---|---|---|
| G1 | 触发需要审批的操作（如工作区外写入） | 弹审批卡：工具、类型、风险、动作/路径、原始请求；run 保持挂起 |

## 4. 键盘速查（默认值，可在 `ctrl+q` 里改）

| 键 | 动作 |
|---|---|
| `ctrl+c` | 退出 |
| `ctrl+n` | 新会话 |
| `ctrl+r` | 会话选择器 |
| `ctrl+x` | 停止当前生成 |
| `ctrl+e` | 最终输出 / 完整过程 |
| `ctrl+p` | 命令面板 |
| `ctrl+o` | 模型（含推理强度） |
| `ctrl+t` | 思考强度 |
| `ctrl+s` | 审批模式 |
| `ctrl+l` | 工作区 |
| `ctrl+d` | 侧栏：显示+聚焦 → 取消聚焦 → 收起 |
| `ctrl+f` | 文件面板 |
| `ctrl+g` | git 浏览 |
| `ctrl+v` | 粘贴（图片或文字） |
| `ctrl+q` | 偏好设置 |
| `shift+←` `shift+→` | 侧栏两个页签 |
| `shift+↑` `shift+↓` | 上一条 / 下一条会话 |
| `/` · `?` · `@` · `#` | 命令面板 · 帮助 · 文件提及 · 会话提及 |
| `pageUp` `pageDown` / `ctrl+↑` `ctrl+↓` | 滚动对话 |
| `esc` | 退一级：浮层 → 上层；滚动状态 → 回到最新 |

没有默认键、只能走命令（`/` 或 `ctrl+p` 面板里输）的：`/refresh`、`/copy`、`/preview`、`/paste`、`/mouse`、`/lang`、`/delete`、`/queue`、`/diff`、`/git`、`/files`、`/help`、`/export`、`/tool-output`、`/reply-detail`、`/compact`、`/tools`、`/providers`、`/history`、`/tree`、`/fork`、`/worktree`。

`/transcript` 没有分页器：执行后只在界面上提示「用 `/export` 导出整份会话、用 `/reply-detail` 看完整过程」。这是有意为之，不是丢失功能。

## 5. 已知限制（不算缺陷）

- 界面文案有中英两套并可切换；**对话内容、会话标题、文件路径、agent 输出不翻译**。
- 图片是「按屏幕格子的预览」，最多放大 6×，不是像素级查看器。
- `/git` 只读；`/diff` 是当前未提交工作区，不按轮次归属。
- 草稿（含图片附件）只在当前进程内保留，不写磁盘。
- 审批「规则并允许」加的规则只对本次运行有效；持久规则仍在桌面端编辑。
- 终端不支持的键（如未上报修饰键时的 `ctrl+enter`、`shift+enter`）会退化；Windows Terminal 需要自己绑一条 `sendInput` 才能拿到 `ctrl+enter`。

## 6. 缺陷怎么记

严重级别：

| 级别 | 判定 |
|---|---|
| S1 阻断 | 进不去界面、会话数据丢失、agent 被 TUI 意外启停、终端退出后没还原 |
| S2 严重 | 主要流程走不通（发不出消息、审批卡死、会话切错、键位做了别的事） |
| S3 一般 | 显示错位、截断、提示文字与实际行为不符、语言/主题不生效 |
| S4 轻微 | 措辞、对齐、图标 |

记录模板：

```
编号：            S级：
版本：future --version  /  gitCommit：
系统 / 终端：    （如 Windows 11 + Windows Terminal 1.22）
终端尺寸：      列×行
模型：
前置 agent：     future host / 桌面端 / future agent
步骤：
  1.
  2.
实际：
预期：
附件：           截图或录屏（.screenshots/ 下自取），debug.log（PI_DEBUG_REDRAW=1 时生成）
```
