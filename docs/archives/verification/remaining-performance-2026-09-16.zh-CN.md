本轮跟进 #664/#665。它实现了剩余的缓存、草稿、传输调度、文件传输/哈希、大块渲染与后台流量工作。它不宣称经过测量的电池节省或原生设备帧率。

## 已实现

### 缓存核算

- 时间线 LRU 计量现在遍历对象/数组/Map/Set 内容，不创建序列化副本，并把显式闭包持有的 projector 存储与排队事件字节计入。共享对象只访问一次。这是保守核算，不是精确的 VM 堆测量。
- 保留既有 8 会话 / 16 MiB 策略；当前选中的对话仍是例外，而不是静默截断可见内容。超大的非活动缓存可在重开时重新加载。
- 共享的已稳定 Markdown 缓存现在除 512 条计数上限外，还有 8 MiB 的源/AST 计费预算。超过 128 Ki UTF-16 码元的源绕过它。计费是序列化结构大小加区块开销，不是精确 8 MiB 堆上限的声明。

### 草稿存储

连续输入时按键以 250 ms 合并、最长等待 2 秒。导航/卸载与进后台会冲刷。读取、显式分享保存、发送清除与确认比对是有序屏障；延迟写入不能复活已清除的草稿或抹掉更新的编辑。与任何防抖持久化策略一样，异步冲刷前的 OS 突然终止仍可能丢失最近的缓冲编辑。

### 网络/解码调度

- 带缓冲的订阅迭代在有界记录数、字节数或耗时工作后让出，然后才进入下一次解密/解码突发。空 SDK 队列本就在等待网络 I/O，因此普通的慢 token 不会各自新增一个定时器。
- 候选代激活按序冲刷有界批次。新到达排在已排队前缀之后；退役一个代会围栏其剩余回调。
- 保留原生 JSON 解析。大型命令回复/历史快照在 UTF-8 解码与原生 JSON 图构建之间让出，使过期的读取可在两个阶段之间被取消。两个原生阶段本身不可抢占。

### 文件传输与哈希

- 以最多四个、约 2 MiB 在途数据的波次拉取不可变索引下载分块；按序写入完成的波次。所有波次 promise 都会安全 settle，失败/取消阻止后续写入，最终大小/SHA-256 校验仍然强制。
- 新的 Android/iOS 原生 `hashFile` 实现在后台队列上以 64 KiB 流式读取，执行既有 10 MiB 上限并复用原生读权限检查。该路径上文件字节不进入 JS。
- 较旧的 App 二进制通过已在使用的 `sha256-universal` 依赖（现直接声明）做有界增量 SHA-256。它会让出并检查取消。原生权限/读取失败不会被静默绕过。原生哈希有界但调用中途不可中断；取消的结果在返回时被拒绝。

### 巨型块

超过小型初始行窗口的表格只绘制这些行，其余行放在一个显式开关后面，而不是挂载所有行：嵌套的垂直视口会把手势丢给消息列表，与同一段里长代码块修掉的是同一个问题。长代码块通过换行保持有界（绝不使用横向滚动区域：手机宽度的块才是 CJK 长行保持可读的关键），并折叠为 16 行裁切预览，其展开开关以内联方式绘制每个有界块，使尾部一次点按即可到达，而不是藏在一个会把手势丢给消息列表的嵌套垂直视口后面。代码块按字符数与行数设界，包括压缩成单行的和大量空行的情形；UTF-16 代理对保持完整。续接标记只是呈现；完整源码复制保留原始代码。

### 协商式详细事件订阅

`selective_events_v1` 允许支持的手机只订阅所选会话的详细事件。后台/列表视图在既有 `state.>` 命名空间上保留低速率 run/审批/配置通知。有意的退订不会被当作网络故障。旧桌面端保留通配符行为；旧手机保留原始全事件流。不引入重新配对或更宽的授权。

维护中的协议规范见 [CONNECTION.md](../../internals/desktop/CONNECTION.md#23-messages-transport-and-permissions)。桌面端到 broker 的详细发布保留以兼容；节省的是对支持手机的不相关详细投递。该特性需要更新后的桌面端以及更新后的移动端 JS。

### 真实 JSON 实验与被拒候选

只读本地 SQLite 轨迹提供了此前测量的 152,394 事件已完成 run 的前 **50,000 个真实事件**，序列化为 events 响应：**8,141,437 字节**。没有编造/重复的事件内容。既有回环探针在 macOS 可见 Chrome 153（上报 hardwareConcurrency 32）中跑了三轮交替 A/B，基线 `85fa2ac4`。这些是 V8/回环测量，不是 Hermes、NATS 射频流量或原生 UI 计时。

一个最初的自定义协作式 JS JSON 解析器虽然正确但发生回退：基线中位 **16.6 ms**，候选 **106.0 ms**；心跳最大延迟中位 **1.8 ms → 7.4 ms**。该解析器已被移除，而不是作为优化发布。

最终保留的原生解析器实现：

| 轮次 | 基线耗时 | 当前耗时 | 基线心跳最大迟到 | 当前心跳最大迟到 |
|---|---:|---:|---:|---:|
| 1 | 15.0 ms | 13.9 ms | 0.5 ms | 1.8 ms |
| 2 | 15.4 ms | 15.1 ms | 2.0 ms | 2.0 ms |
| 3 | 13.7 ms | 13.8 ms | 1.7 ms | 1.2 ms |

应视之为吞吐相当加上一个取消/任务边界，**而不是显著加速的证据**。所有解码内容摘要一致：
`52497c31fce090983e5a10aedaba9b78fe1e87a314cef216c691637c3f3c8003`。

用 `node scripts/measure-mobile-performance.mjs 85fa2ac4` 复现，然后 `python3 scripts/serve-mobile-performance.py`，打开输出的回环 URL 并使用“Measure large real JSON decoding”。服务器从不启动/停止真实 agent，不读取凭据，也不提交原始对话。结束后只停止打印的测量 PID 并关闭其标签页。
