## 历史 Windows 基线失败——经集成 #596 解决

第一次完整桌面 `cargo test` 在 #596 之前尝试。除随后修复的 v2 fixture 更新外，
它在未更改的 Windows 路径/Git fixture 上失败，并在打印最终完整套件汇总前超过命令时间预算。在 `05da063a` 处干净、分离的 worktree 独立复现：

- `git_review::tests::git_output_returns_stdout_and_errors_on_failure`：
  `git_review.rs:600`，在只读打开句柄上的 `File::set_modified` 返回
  Windows 错误 5（`PermissionDenied`）。
- `commands::files::tests::best_effort_canonical_resolves_each_shape`：
  预期 `/definitely/not/here/x/y/z.txt`，得到 Windows 规范
  `\\?\D:\definitely\not\here\x\y\z.txt`。
- `canonical_or_raw_canonicalizes_existing_and_falls_back` Git fixture 也在该干净基线上复现相同的 `set_modified` 错误。

这些文件未被 E2EE 分支更改。这是这些特定基线失败的证据，不是笼统声称每次完整套件失败都无害。后续上游修复 `824e0243`（#596）解决 Windows 基线问题。合并它之后，保留加密测试断言并匹配断开通知而非假设到达顺序，完整 Windows 套件以上述计数通过。更早的范围 pass 未替代该次运行。

## Desktop-JS 记录微基准

命令：`npm test -- --runTestsByPath src/remote/__tests__/secureChannel.perf.test.ts`
在 `mobile/` 下。Node `perf_hooks` 计时，每用例 100 条预热记录；每个样本包括加密与鉴权解密，但不含网络、JSON、UI、IPC 桥或手持设备能耗测量。密钥是固定公开测试密钥。

| 明文 | 样本数 | p50 | p95 | 额外线上字节 |
| --- | ---: | ---: | ---: | ---: |
| 128 B | 2,000 | 0.068 ms | 0.133 ms | 44 |
| 1 KiB | 1,000 | 0.086 ms | 0.191 ms | 44 |
| 64 KiB | 100 | 1.597 ms | 2.227 ms | 44 |

这些是一次本地 Jest/Node 测量，不是 Android/iOS 延迟保证。
重放跟踪使用固定大小环形做常数时间检查，而非在每次流式更新时扫描 4096 记录窗口。
