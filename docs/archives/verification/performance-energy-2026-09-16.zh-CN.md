# Mobile TS 性能与能量开销削减 — 2026-09-16

> 本文是历史快照 [Mobile TS performance and energy-work reduction — 2026-09-16](./performance-energy-2026-09-16.md)（2026-09-16，基线 `8d96b076`）的忠实逐段中文翻译，保留原文结论、时间与 commit 边界；译文不是新的复核结论。

## 范围与局限

本次改动减少实时投影工作量、普通文本更新频率、冗余的呈现定时器与 Markdown 重复解析。它**不是**经过测量的电池续航改进。

测量在 macOS 上真实可见的 Chrome 153 浏览器中进行（V8，上报 hardwareConcurrency 32），使用打包后的**生产 Mobile TypeScript** 与真实本地历史对话数据。基线：`8d96b076`。当前：与本报告一同提交的代码。每个场景三轮，A/B 顺序交替。未使用假时钟或合成/重复的 token 内容。表中报告的是中位数。

该测量工具并非原生 React Native 应用：它不测量 Hermes、原生文本布局、FlatList 回收、IME、原生返回手势、NATS/加密、真实手机射频/网络时延或功耗。它的心跳是 16 ms 的 JS 定时器迟到探针，不是帧率或原生触摸到绘制时延。突发耗时包含生产调度与投影，不只是 CPU 时间。定速场景刻意每 10 ms 提供一个真实事件；这些**不是**原始事件的时间戳。

## 已实现的改动

- 把普通文本/思考/工具参数增量按 80 ms 合并（稳定流量下约 12.5 次更新/秒），取代 16 ms。控制/审批/错误/结束事件绕过该等待，同时保持队列顺序。
- 在每个有界实时批次内，只复制一次去重/projector 状态，并按连续片段物化快照，而不是每个 token 一次。保留 64 次操作 / 8 ms 的协作预算；积压续跑时直接让出，不再等待另一个 80 ms。
- 移除第二个 32 ms 打字机定时器。直接显示已合并的提交文本。保留新插入区块原生淡入的 reduced-motion 处理。
- 只有末尾片段保留流式呈现订阅；已完成的文本片段不再保留实时呈现订阅。
- 已用时长标签从每秒两次改为每秒一次，并在后台停止其定时器。
- 连接的背景宽限期跳过时间线投影。既有前台对账会恢复错过的持久数据；进入后台不会中止远程运行。
- 保留带行内链接、图片与任务列表的稳定 Markdown 区块/行。当新解析出的定义/脚注可能影响前面的区块（包括嵌套在容器中的定义）时，回退到整文档规范解析。保留本地文件/图片引用收集。

## 本地复现

在仓库根目录、已安装常规 JS 开发依赖的前提下：

```sh
node scripts/measure-mobile-performance.mjs 8d96b076
python3 scripts/serve-mobile-performance.py
```

在可见浏览器中打开 `target/mobile-performance/ready.json` 里的回环 URL。先使用真实轨迹 A/B 按钮，再用真实 Markdown 按钮。后者保留之前的聚合结果。查看 `target/mobile-performance/results.json` 获取每轮指标。不要在浏览器测量期间并发运行 CPU 密集型测试/构建。所选本地语料可能变化，因此跨机器或跨日期比较测量前先比较指纹/计数。

默认服务器启动器会打印其子进程 PID；结束时只终止**那个测量服务器**并关闭测试标签页。它有 30 分钟生存时间上限。所有生成的产物均被 gitignore。无需 Rust agent 或模型请求。

## 仍需电池与真机验收

已展示的能量代理指标是更少的提交/重复投影、没有次要打字机唤醒、更低的时长定时器频率以及无后台时间线投影。射频流量与模型执行未变。未测量任何电池百分比或瓦数。

发布设备后续应比较等量工作负载与相同亮度/刷新设置下的代表性 Android/iOS 手机：CPU/GPU 活动、热行为、前台/后台能量、帧节奏，以及实际的返回/停止/键盘时延。还应测试文件预览浮层与大型原生 Markdown 布局；这些仍是独立的优化机会。
