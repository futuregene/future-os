# FutureOS 终端界面（TUI）

`future tui` 是全屏终端界面：它占有整块屏幕、重绘绝对行、用「画过什么」来解析鼠标点击。
它取代了之前的行内 TUI（把行追加进终端自身的 scrollback、只对尾部做 diff）——那套界面、
它的代码和它的页面都已删除，不是标记弃用。

设计契约见 [`docs/tui/workbench-spec.zh-CN.md`](../tui/workbench-spec.zh-CN.md)。

## 怎么跑

```bash
future tui                          # 终端界面（启动目录就是新会话的默认工作区）
future tui --session <id>           # 打开指定会话
future tui --continue               # 最近活跃的那个
future tui "看看这个挂掉的测试"      # 启动时直接发第一条消息
future tui -p "这个报错是什么意思"   # 只问一句，不开界面

# 只跑界面，确定性演示数据（不连 agent，标题栏写 demo）
cargo run -p future-tui --example workbench_demo -- --scenario chat

# 任意尺寸打一帧：截图或检查布局
cargo run -p future-tui --example workbench_demo -- --scenario launchpad --width 120 --height 38
cargo run -p future-tui --example workbench_demo -- --scenario chat --plain     # 去掉 ANSI

# 鼠标验收（120x38 与 90x24 两档命中区域）
cargo run -p future-tui --example workbench_demo -- --self-test

# 逐页用真实按键与鼠标事件驱动（命中区、帧尺寸、可达状态）
cargo run -p future-tui --example workbench_interaction -- --size 120x38
cargo run -p future-tui --example workbench_interaction -- --size 40x12

# 以及行为层：指针下面的那一行，打开的真的是那一行吗
cargo run -p future-tui --example workbench_semantics
```

场景：`launchpad`（还没有会话）、`chat`（一轮对话，过程折叠成一行汇总）、`workspaces`
（十二个工作区和它们的会话，用来看侧栏的滚动窗口和 `↓ N more`）。

## 一帧长什么样

```
 头部（2 行：会话 · workspace · 按钮 · 版本，随后细分隔线）
 ──────────────────────────────────────────┬──────────────────────
 对话（底部对齐，向上有 ↑ 更早）            │ 侧栏：最近 工作区
                                            │ ▸ 会话标题  future-os · 2m
                                            │
 输入框（❯ 多行草稿，可增高）               │  （侧栏一直延伸到输入框旁边）
 活动行：⠋ 思考 … · 3s · 2 工具                      42 tok/s · 缓存 96%
 状态栏：model · effort · 审批模式   ░░ ctx 6.9k/1.0M 0.7% · ≈¥0.01
 提示行：Esc 回到聊天 · ctrl+d 侧栏 · ctrl+p 命令 · ctrl+q 偏好设置
```

提示行只教**入口不在屏幕上**的键：`ctrl+r` 不在里面，因为头部上的 `[ctrl+r] 会话` 按钮已经把
那个键写在了上面一行，`ctrl+f`/`ctrl+g` 也挂在各自的按钮上。读者要用的键不会只在帮助浮层里出现，
也不会在一屏里被教两遍。

侧栏是一个**整列**，不是停在某个分区前面的一块：它（连同分隔线）从头部下面一直铺到底部三行
之前，所以输入框左边那块是侧栏的背景，而不是空着的画布。底部三行——活动、状态、提示——
仍然占满整行宽度。输入框这一带正好就是它画出来的三行（上边框、输入行、下边框），不再多留
一行空白。

侧栏是一个**任务面板**，分两个页签。**最近**（默认）列出全部会话——名字一行，它所在的工作区
和刷新时间一行——最新的在前。还在跑的那条排在最前，单独一组叫**活跃**，状态栏位是一个转动的
spinner；其余的在**更早**下，两组标题都带各自的条数（桌面端 recent 视图的样子搬到侧栏里）。
两个标题只在真的分成两组时才画：没有在跑的会话时，列表就是列表。行里的工作区写的是**名字**
（`future-os`），不是路径：侧栏只有
30 多列，被截断的路径比这个名字说得更少。**工作区**按桌面端侧栏的方式归档同一批会话：先
**置顶**（用 `p` 置顶的工作区），再 **工作区**（每个工作区一个标题，会话在其下），最后
**对话会话**（不属于任何工作区的会话，即 app 自己的临时目录）。用量数字在状态栏，面板不再
重复；技能属于命令面板。页签只由 `shift+←` / `shift+→` 切，在任何地方都行；侧栏拿到键盘焦点时也一样——普通 `←`/`→` 始终是草稿光标的，因为侧栏立着的时候输入框还在屏幕上。点页签也是一样的切换。

两个页签列的是同一批会话。折叠（在工作区标题上按 `enter` 或点它）记在
`~/.future/tui/settings.json`（`foldedWorkspaces`），下次启动就已经生效。搜会话是历史选择器
（`ctrl+r`）的事——它自己那行就在边输边筛，所以侧栏不再画搜索行：在侧栏按 `/` 和别处一样
打开命令面板。

侧栏有两个页签：最近、工作区——都是关于整个 agent 的会话列表。当前会话自己的目录树
**文件** 是一块单独的浮层（`/files`，或 header 上的 `[ctrl+f] 文件` 按钮）。
文件一次只列一层，而且是**打开时才读**：仓库里有 `node_modules` 也不会卡，每层最多列 400 项
并写明截断。`↑`/`↓` 走行，`enter`（或 `→`）在目录上是展开、在文件上是预览，`⌫`（或 `←`）
收起目录（否则跳到它所在的目录），`r` 重读目录，`esc`/`q` 关闭。点击等同于该行的 `enter`。
换会话后树会重读：这块面板和 `/git` 一样只作用于当前会话。

## 图片

`ctrl+v` 读剪贴板：剪贴板里是图片就变成**草稿附件**（输入框标题会写 `· 📎 2 张图片`），是文字就
粘进草稿。图片仍用输入框已经认识的 `[Image #N]` 标记携带，跟拖入一个文件同一条路线，随 prompt 一起
发出；`/preview` 打开草稿里最新那张图。`/paste` 是同一个动作的命令面板入口——它在那里是因为
Windows Terminal 把 `ctrl+v` 绑成了自己的粘贴（带不了图片），在那个终端里这个键根本到不了 TUI。

对话**里的**图片就是它的文件名，链到那个文件——一行文字，**不在聊天里内联画出图片**。随消息带来的
图片把附件的名字画成链到路径的链接，就在它所在的那个气泡里；agent 写的 markdown `![说明](路径)`
同样画说明文字（没有说明就画路径）并链到那个文件，正文里写出的一张确实存在的图片路径也算目标。
`tab` 选中的是这一行（一张图一个落点），`⏎` 或鼠标点它，就把文件在预览框里打开——图片在框里，全
尺寸、可缩放、可平移；聊天本身不留图。**你自己发的**图片也一样：记录里存的是附件路径而不是图片
本身，所以显示的是磁盘上那个文件（如果它还在）。聊天不再为缩略图留任何行，四条截图就是四行而不
是四块，周围的回答始终在视野里。位图只属于预览框：有东西要看时才在后台线程上读盘、解码，框一关
就不再保留。终端自己的 `cmd`/`ctrl`+点击打不开它：它把目的地交给浏览器，而文件和会话链接都不该
去那里。

TUI 里图片走终端的**图形协议**：位图按格子摆上去（kitty 的 `a=T` 放置，一个画面一个来源，
之后每帧只重放位置；iTerm2 的内联图片只在它覆盖的格子被重写、或显示区域变化时重发），所以是真的图片而不是字符画。预览框（在文件页签上对图片按 `enter`，或对
附件按 `/preview`）顶部一行就是它的控件：`[缩小] [2x] [放大] [适应]` 与 `[上一张] 2/5 [下一张]`，
都能点；键盘是 `+`/`-`（或滚轮）放大到 6×、`[`/`]` 换同目录的上一张/下一张、`0` 复位。
缩放后鼠标**按住图片拖动**即可平移（方向键同样可以）。终端不支持图形协议时，框里给出尺寸和一句
说明，而不是拿字符去糊一张图；同目录只有一张图时不会出现翻页按钮。
文档——Markdown 渲染后、其它按行显示——用 `↑`/`↓` 和 `pageUp`/`pageDown` 滚动。读不了的文件会
说明原因，而不是开一个空框。

launchpad 是**正文**，不是盖在对话上的弹窗：没有会话时整块屏幕就是输入界面（名称、
输入框、工作区 / 模型 / 强度 / 审批四个可点参数），底部不再重复画输入带。
整块内容在正文里**上下居中**，不再贴着头顶；会话列表也只由侧栏负责、这里不再重复。
`tab` 在输入框和参数之间移动，`enter` 循环当前参数，打字或 `escape` 把键盘交回输入框。
这一块自己不教按键：按键已经在底部的提示行里，输入框除了一句话之外还收什么
（`/` 命令、`@` 文件、`#` 会话）写在 placeholder 上，正是准备打字的地方。四个参数就是桌面端
输入框自带的那几项（模型、思考强度、审批模式）再加本 TUI 自己的起点——工作区。工作区的默认值：
`cd 项目 && future tui` 时就是**启动目录**（第一条消息直接在该项目里建会话）；从「环境目录」
（家目录、临时目录、根目录）启动时是**上次选过的工作区**（`settings.json` 的 `lastWorkspace`，
这样在随便哪个目录里敲 `future tui` 都不会再把会话归到一个叫 `tmp` 的工作区下）；从 app 自己的
临时目录启动、或者显式选了「对话会话」时是**对话会话**（不绑工作区，跑在桌面端同款的
`~/.future/workspaces/chat/<会话 id>`，侧栏归到 对话会话）；`/new`（`ctrl+n`）则继承刚离开的那个
会话的工作区——聊天会话不继承，下一条消息会建自己的 chat 目录。记住的工作区已经不存在（比如
worktree 被删）时跳过。其余三项没选过时显示的是产品
默认值：agent 的默认模型以及它起步的那一档强度、**完全访问**。第一条消息就用参数上写的东西建
会话，所以参数不会写着会话实际不走的值；没有单独的「权限」项，因为别的客户端都没有这个选择。

**只有一个前缀：`ctrl`。** 默认键里不再有 `alt`——macOS 上 Option 默认是输入特殊字符，除非读者
自己打开「Use Option as Meta」，所以 `alt` 快捷键在这块界面每天被开发的那个终端里等于不存在；
默认里也没有功能键（`F1`–`F12` 在笔记本上要按 `Fn`，紧凑键盘干脆没有）。

组合键是：`ctrl+c` 停止当前运行、`ctrl+n` 新会话、`ctrl+r` 会话、`ctrl+d` 侧栏、`ctrl+x` 退出、
`ctrl+p` 命令、`ctrl+o` 模型、`ctrl+t` 强度、`ctrl+s` 审批模式、
`ctrl+l` 工作区、`ctrl+f` 文件面板、`ctrl+g` git 浏览、`ctrl+v` 粘贴、`ctrl+q` 偏好设置，
以及 `ctrl+1`/`ctrl+2` 侧栏的两个页签。其余动作走**命令或点击**：
`/delete`、`/pin`、`/queue`、`/copy`、`/mouse`、`/preview`、`/refresh`、`/lang`、`/reply-detail`、
`?` 帮助——帮助浮层只列有键的行，没键的动作就是上面这些命令入口（所以那里不再出现 `—` 占一行）。

字母只能用到这些，因为剩下的都撞车：终端把 `ctrl+h`/`i`/`j`/`m` 发成退格、Tab、换行和回车；
`ctrl+a`、`ctrl+b` 是 `screen` 和 `tmux` 的默认前缀；`ctrl+z` 在别处是挂起；`ctrl+u`/`k`/`w`/`y`
是输入框自己的编辑键。`ctrl+e` 也归输入框——它是 shell 里的「行尾」——原来是地图借走的：按一下会把
整份转录重新折一遍，而一个光标移动绝不应该有这种后果（它切换的阅读档位现在只走 `/reply-detail`）。
侧栏拿的是 `d`（它像抽屉一样滑进滑出），这个字母是「删除会话」让出来的：
删除要弹确认、也不常按，留在 `/delete` 上就够（`delete` 键是草稿的前向删除）。

`ctrl+c` 是唯一一个含义不归我们定的字母。raw 模式关掉了 `ISIG`，这个字节是以按键身份到的，
但读者对它的期待来自 shell：**中断正在跑的东西**，而不是关掉 shell。绑给正在跑的这一轮，它就是
这个意思；没有 run 在跑时则什么都不做——不发请求、也不出提示。退出是 `ctrl+x`，别的终端程序都不教
这个键，所以它不会被顺手误按；而且退出是无损方向：会话和它里面的 run 在 agent 上原样留着。
两者都不归浮层吞：退出键在浮层处理之前判，中断键只属于主界面，所以模态永远拿不走出路。

全部都能在 `/preferences`
里改键，帮助浮层按用途分组列出。

## 文件与引用

`@` 从当前会话的工作区补全文件。带空格的路径会以引号插入（`@"docs/my note.md"`），
提交时按一个路径读取。agent 收到的是文件内容的 `<file>` 块（最多 8 个文件、每个 256 KiB）；
太大、二进制或读不了的文件会连同原因写进 prompt，而不是无声丢掉。正文里只是包含 `@` 的普通文字
（例如邮箱地址）不算引用。同一个补全浮层里的 `#` 用来引用会话。

两个断点都来自契约：

- **宽 < 88**：侧栏收起，`/recent`（或 `shift+←`）改为把当前面板全屏打开。
- **高 < 24**：头部压成 1 行，输入框只留上边框，活动行隐藏。

每一帧都恰好是 `height` 行、每行恰好 `width` 个显示列（CJK 与 emoji 计 2），1×1 也一样——
这条不变量由帧测试和唯一负责补齐的 `ansi::fit` 共同保证。

## 界面语言

界面有中英两套，**界面文案**（页签、选择器、按键提示、空态、提示行）按读者的语言绘制。
**内容**不翻译：对话、会话标题、文件路径、agent 的输出，写成什么就是什么。

默认跟随系统，读者选过之后记在 `~/.future/tui/settings.json`（`language`：`system` |
`zh` | `en`，与桌面端、手机端同一套词汇；缺这个键就是 `system`）。

- `/lang` 打开选择器：**跟随系统**、**中文**、**English**。
- 语言依次取 `LC_ALL`、`LC_MESSAGES`、系统自己的答案（macOS 的偏好语言
  `AppleLanguages`、Windows 的界面语言）、`LANG`。`LANG` 放最后是因为 Mac 的 shell 从
  `/etc/zprofile` 取 `LANG`，那是终端的习惯、不是这台机器的选择——否则系统是中文的 Mac
  会画成英文。缺失或 `C` 都按英文。
- `cargo run -p future-tui --example workbench_demo -- --lang en` 可以打一帧英文界面；
  截图流程把 `zh` 写进它自己的临时 home 固定下来，基线不因谁跑而变。

文案集中在一张表 `tui/src/workbench/i18n.rs`，两种语言写在同一行：只加一种语言的键编译不过。

## 按键与鼠标

| 按键 | 动作 |
|---|---|
| `tab` / `shift+tab` | 对话里：按阅读顺序逐个选中所有“能打开的东西”——**链接和图片**，以及聊天自己的**行**（折叠的一轮、一段工作、一次工具调用、一行 `▸ 思考`）。选中的那一处反色显示，聊天自动滚到它。`enter` 打开：链接交给浏览器 / 切会话 / 在预览框打开（见下）；**行**则打开它藏起来的东西——折叠的一轮就地展开成它代表的那几行（表头由 `▸` 变成 `▾`，表头下那一行接着打竖线，导轨与 `▾` 同列）、一段工作展开成它代表的每次调用、工具调用显示正文、思考标记显示正文——再按一次 `enter`（或再点表头）收起。打开后的树里每一行仍然可以单独打开：`▸ 思考` 显示推理正文，工具调用显示输出——它们再缩进一级、另起一条导轨；答案留在树外面，因为它是这一轮的回答而不是过程。launchpad：在输入框与参数行之间移动（`enter` 循环光标所在那项，`escape` 或打字回到输入框）。侧栏从不**抢**键盘：作用在侧栏上的键都带 `shift` |
| `←` `→` | 移动草稿光标。它们从不切页签：那是 `shift+←`/`shift+→` 或 `ctrl+1`/`ctrl+2` |
| `↑` `↓` | **滚动对话**，一次一行，永远如此：这两个键只属于对话记录，草稿不接它们（写 prompt 用 `←`/`→`、`home`/`end` 和下面那些组合键） |
| `shift+←` / `shift+→` | 在侧栏的两个页签（最近 / 工作区）之间轮换，光标在哪都行：侧栏会被显示出来，光标落在屏幕上那条会话上。两个方向都循环 |
| `ctrl+1` / `ctrl+2` | 直接点名一个页签：最近 / 工作区，按页签条的左右顺序（需要终端上报修饰键；`shift+←`/`→` 在任何终端都能轮换） |
| `shift+↑` / `shift+↓` | 在侧栏里走，光标在哪都行。**最近**里每一行都是一条会话，所以每走一步就切换：光标跟着走，对话在**你停下的那条**才打开（最后一次重复之后 80 ms），按住经过的那些不会被加载；已经读过的会话直接从内存回来，没有任何等待。**工作区**里光标也会停在工作区标题上，停在那里不切会话——按 `⏎` 才是打开 / 收起那个工作区。一个功能只给一个键：`ctrl+↑`/`ctrl+↓` 不是这一步——macOS 把它给了 Mission Control，在那个系统上这个键根本到不了终端 |
| `shift+pageUp` / `shift+pageDown` | 翻侧栏的列表——和在侧栏上滚轮是同一件事。侧栏光标（也就是屏幕上那条会话）不动 |
| `/pin` | 置顶 / 取消置顶侧栏光标所在会话的工作区（工作区页签的**置顶**区）。没有默认键：`p` 在草稿里就是一个字母 |

鼠标上报使用 SGR 1006，启动时读取保存的偏好（默认开启）；`/mouse` 可以在运行时释放 / 恢复捕获并保存选择，退出时总会还原终端。草稿的文字、光标、折叠粘贴和图片附件按会话保留，经过浮层、launchpad 和会话切换也不丢失（仅在当前 TUI 进程内，不写入磁盘）。

对话默认跟随最新输出。手动向上滚动后保持阅读位置；新输出只显示提醒徽标，不把读者拉回底部。滚回底部或按 `esc` 恢复跟随。

驱动只重绘有变化的帧：空闲时没有 120ms 定时重绘。流式输出与 spinner 更新按 80ms 合并，输入与 resize 立即重绘；转录按宽度和内容版本缓存。一帧里只向终端写变化的行（宽或高变化时整屏重绘），流式 token 不会每帧重发整屏。终端输入按**整批**读取再处理（一次最多 64 个事件），按住一个键只付一帧的代价；同一批里的会话步进还会合并成**一次**切换（换会话是两次往返加一次转录加载，按重复次数各做一次就是之前卡顿的原因）。减少动态不调度动画重绘。

## 布局与个性化

头部是两行上下文：会话标题与工作区、打开会话列表和两个面板的按钮、连接状态，下面一条分隔线；同样的 38 行终端把剩下的行都留给对话。窄行把格子先花在按钮上：先去掉版本号，再去掉品牌字，再从右往左去掉面板按钮，会话列表按钮留到最后——侧栏是键盘面板，窄屏下它根本不在对话旁边，所以手机大小的终端也能一键点开会话列表。`ctrl+q` 打开偏好面板，`↑↓` 选行、`←→` 调整——面板里列的就是这个终端客户端记住的全部东西：

- **侧栏位置 / 宽度 / 显示**：左侧 / 右侧，30–60 列（拖动分隔条或在面板里调整，松手即写入 `sidebarWidth`），以及显示 / 收起。收起后也可以在面板里重新显示，不必记得 `ctrl+d`。
- **界面语言 / 配色主题**：这两行是菜单而不是开关，`enter` 打开的就是 `/lang` 和 `/theme` 那两个选择器，选完或按 `escape` 回到面板停在原来那行。
- **鼠标与通知**：保存启动及运行时的鼠标偏好。本 TUI 提交的运行成功结束、无排队后续且终端失焦时通知；审批与错误无论焦点都提醒，并按请求 id / run id 去重。取消、历史回放和其他客户端的运行不通知；不支持焦点上报时按已聚焦处理，不延迟发送前台完成通知。`notify.enabled` 是总开关，`notify.bell` 与 `notify.osc9` 分别控制提示音和终端桌面通知序列；实际投递取决于终端支持，文本会清理控制序列、压成单行并限制长度。
- **减少动态**：关掉动画，流式正文照常立即到达，不改变 agent 行为（没有默认键，就在这一行按 `enter`）。
- **主题**：`/theme` 打开主题选择器，除了一直有的六套（`dark`、`light`、`one-dark`、`one-light`、`high-contrast`、`dracula`），还加上桌面端那一族（`ayu`、`catppuccin`、`everforest`、`gruvbox`、`kanagawa`、`nightfox`、`nord`、`rose-pine`、`solarized`、`tokyo-night`、`vesper`，以及 catppuccin、everforest、gruvbox、rose pine、solarized 五套的 `-light` 版本）。选择保存为 `themeId`，两块界面同时换色。未保存主题时用 `COLORFGBG` 跟随终端浅色 / 深色（未知值回退深色）；存在 `NO_COLOR`（包括空值）即禁用样式。
- **快捷键**：`enter` 进入编辑器，选中动作后按新组合键。冲突会与原占用者交换，不会出现一个按键同时触发两个动作；`r` 恢复默认，`escape` 取消捕获或返回。复制、队列、鼠标和减少动态同样是可重绑的上下文全局动作；浮层保留局部按键，避免全局键误提交审批或误改历史搜索。

偏好与快捷键列表在矮窗口中跟随当前项滚动并保留底部提示。所有选择立即写入 `~/.future/tui/settings.json`（`sidebarPosition`、`sidebarWidth`、`sidebarVisible`、`mouseCapture`、`notify`、`reducedMotion`、`language`、`themeId`）；快捷键的增量覆盖在同级 `keybindings.json`，键名为稳定动作 id，例如：

```json
{
  "commandPalette": "ctrl+p",
  "sidebar": "ctrl+j"
}
```

没有存过 `sidebarVisible`（第一次打开，或配置文件早于这个键）时侧栏默认**收起**：对话占满整个宽度，`shift+←`/`shift+→` 把它叫回来（切页签时也会显示它）。读者一旦显示或收起过，下次启动就从那个选择开始；偏好面板里的「恢复默认偏好」回到同一个收起状态，同时把语言交还系统、把配色交还终端的浅色 / 深色提示。侧栏宽度按拖动到的值原样写回：文件里的范围就是分隔条自己的 30–60，下次启动不会把它悄悄收窄。

支持 `Ctrl/Alt + 字母或数字`、`F1`–`F24`、`Tab`、`Escape`、`Enter`、`Home`、`End`、`PageUp`、`PageDown`。非法或未知配置会逐项忽略，不会导致启动失败。帮助浮层、底部提示与事件分发读取同一份键位，修改后三处同步。

配置文件也可以直接编辑：

```json
{
  "sidebarPosition": "right",
  "sidebarWidth": 36,
  "sidebarVisible": true
}
```

| 审批 | 请求挂起时打开完整卡片，显示工具、类型、风险、动作/路径、原始请求和 sandbox 边界。`y` / `n` 允许一次或拒绝；`a` 先添加 agent 建议的**本次运行**工作区规则再批准，规则失败则请求仍保持待决。Esc 只收起卡片，不作决定 |
| Diff 审查 | `/diff` 列出会话工作区已跟踪与未跟踪改动，并显示选中文件的真实 git patch。宽终端保留固定文件导航，旁边的补丁独立滚动；窄终端用 `tab` 在文件与补丁间切换。上下键操作当前视图，左右键选择文件。箭头立即跟随光标，`·` 标出补丁已加载完的那个文件（重新读取还在路上时）。`r` 刷新；这是当前未提交工作区，不是按轮次归属，patch 预览有大小上限 |
| git 浏览 | `/git`（或 `ctrl+g`）是仿 tig 的只读面板，四个视图：提交（`git log --graph`，横跨所有分支、标签与远程分支，最多 200 个，带 decoration）、引用（本地/远程分支与标签，带 upstream 跟踪）、改动（工作区，与 `/diff` 同一份 porcelain 读取）、储藏（`git stash list`）。日志画成泳道图：一条分支线一种颜色，选中行是横贯列表的底色带；右侧详情按内容上色：hunk 头、增删行、diffstat 的横条、提交自己的头部。选中行会加载详情：提交的 stat 与 patch、引用的 upstream 与 tip、文件的 patch、stash 的 diff。`1`–`4` 切视图，`tab` 切列表/详情（宽终端从 108 列起两边同时显示），`↑`/`↓` 走行，`PgUp`/`PgDn` 翻**详情**（详情才是长的那一侧，所以按键在列表上时也归它），`enter` 打开（引用＝按它过滤日志、改动＝在预览框打开文件、提交＝把按键交给 patch），`y` 复制 sha/引用名/路径，`backspace` 清除过滤，`r` 重读。这里不 stage、不 commit、不 checkout、不 drop stash；每次查询都有超时，到期就杀掉 |
| 历史搜索与树 | `/history` 筛选当前 `list_sessions` 的标题/首条消息预览、目录与 id；`/tree` 使用 `parentSessionId`。回车打开所选会话 |
| 浮层列表 | 一条记录固定占一行：上下键正好走一行，长标题就地缩短而不是折行（折行会让一次按键跨过两行）。放不下的字段整块丢弃——工作区路径从中间截断会读成另一个目录——所以窄框里依次是标题、标题 · 工作区、再加 id。`pageUp`/`pageDown` 按一屏移动光标（审批卡这类详情视图则滚动；diff 跟随当前有焦点的半边） |
| `/worktree` 列表 | `›` 是选择；`●` 表示会话已经在这个工作区，所以即使当前行是第一行，选择也看得见 |
| Fork | `/fork` 列出 `get_fork_messages` 的真实用户消息节点；回车调用 `fork` 并打开子会话 |
| Worktree | `/worktree` 列出真实 git worktree，回车设为会话目录；`/worktree new <branch>` 在 `.worktrees/` 下创建并移动会话。不提供 remove/prune/reset/clean |
| 已有设置入口 | `/mode`（或 `/sandbox`）打开审批模式选择框，`/thinking` 打开思考强度选择框，`/compact [说明]`、`/tools a,b` 或 `/tools off`、`/providers`；`/skills` 与 `/model` 保留已有界面 |
| 会话面板 | `list_sessions`，最新的在前：最近页签分成**活跃**（还在跑的会话，行的状态位是 spinner）和**更早**两组，两组都有内容时才画标题。侧栏在屏幕上时每五秒重读一次列表——别的客户端起的 run 没有别的途径能到这一端。工作区页签按目录归档、置顶的排在前面。置顶记在 `settings.json`（`pinnedWorkspaces`） |
| 用量 / 上下文 / 成本 | `get_state` 的 usage，随同样的事件刷新 |
| `ctrl+n` / `/new`、`ctrl+c` 停止、`ctrl+k` 刷新 | |
| launchpad 参数 | 点「工作区 / 模型 / 强度 / 审批」循环切换。在 launchpad 上，工作区、模型、强度与审批模式都是替「第一条消息将要创建的会话」暂存的（此时 agent 还没有会话可设）；已有会话时直接走 gRPC。工作区默认值：`cd 项目 && future tui` 时是启动目录；从家目录、临时目录、根目录这类「环境目录」启动时是上次选过的工作区（`lastWorkspace`）；从 app 自己的临时目录启动、或选了「对话会话」时是对话会话（不绑工作区，建会话时在 `~/.future/workspaces/chat/<会话 id>` 下建目录）；`/new` 继承刚离开那个会话的工作区（聊天不继承）。模型与强度写产品默认值：agent 的默认模型与它起步的那一档强度，审批是完全访问——第一条消息就用这些建会话。工作区 chip 在「对话会话 + 本客户端有会话的目录」之间循环，提示行写出选中目录的完整路径 |
| 主题 | 存 `~/.future/tui/settings.json`（`tui/src/settings.rs`）；阅读档位故意不存——`/reply-detail` 只管本次运行 |

## 还没有的部分

- **预览就是预览**：图片按屏幕格子摆放，最多放大 6×；要逐像素看请用系统图片查看器。图片解码在本机完成，TUI 不会把图片数据传到任何地方。
- **命令面板**只列适配层实现的命令。提供商与工具管理采用紧凑入口（`/providers`、
  `/tools`），`/skills` 仍列在命令面板里。审批允许规则仅本次运行有效；持久化规则文件编辑仍在桌面端。
- 后续增强：时间线轨、会话管理器全屏版、全屏草稿编辑器。
