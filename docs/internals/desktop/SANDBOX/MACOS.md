## 1. Design and implementation

`agent/src/sandbox/seatbelt.rs` compiles the RuleSet into SBPL, and
`PreparedShell` launches `/usr/bin/sandbox-exec -p <profile> <shell> -c
<command>` with the same selected Unix shell as the unwrapped tool (`$SHELL`
when it names bash/zsh, otherwise the first bash/zsh on PATH, otherwise `sh`).
There is no Linux-style mount helper, and host ACLs are not modified.

- The profile starts from `(deny default)` and allows fork/exec/process-info,
  same-sandbox signals, pseudo-tty, sysctl-read, mach-lookup, ipc-posix,
  file-ioctl and other operations development tools need; these system
  interfaces are currently broad — no claim of a least-privilege syscall
  sandbox.
- Default `(allow file-read*)`; writes are open for the workspace,
  `temp_roots()`, and `/dev/null`, `/dev/zero`, stdout/stderr, `/dev/fd/*`, tty,
  dtracehelper and similar pseudo-devices.
- Network uses `(allow network*) (allow system-socket)`; no network cutoff or
  domain filtering.
- RuleSet layers and intra-layer order are both emitted in reverse: lowest to
  highest priority, so SBPL last-match corresponds to the engine's first-match;
  overrides take effect last. Read and write are emitted separately; both ask
  and deny are OS-level denies.
- Ordinary non-wildcard rule matchers become `subpath`; single-command file grants become `literal` (**not** an existence
  check first and then a literal choice); globs use regexes generated by the
  rule engine. Only the `*`/`**`/`?` semantics the implementation supports are
  guaranteed; SBPL regex capability is not claimed to equal all shell globs.
- Path normalization handles `/private` targets of `/tmp` and `/var`; SBPL
  string escaping escapes double quotes and backslashes to avoid path injection.

Rules apply to subsequent file operations, not to a file enumeration at launch.
So a missing `.env`, a future `.pem`, and a rename to a protected target inside
an allowed parent directory still hit the profile; this is the core difference
from the Linux mount snapshot and Windows ACLs.

The Agent's Unix process-group termination logic handles timeout/abort. Native
read/write/edit resolve rules inside the Agent process first. The old draft's
standalone `run_grep` / `run_ls` to-dos no longer correspond to the current
tools implementation; grep/ls invoked through a shell are wrapped with that
command — no claim that arbitrary new subprocesses/MCP automatically gain
coverage.

## 2. Approval and unavailability behavior

The model declares concrete paths before execution with `additional_permissions.read/write`. Approval produces a Seatbelt profile for that command only: file uses literal, subtree uses subpath. Explicit denies cannot be overridden and session rules are not changed. Request format and UI are described in [COMMON §5.1](COMMON.md#51-macoslinux-single-command-execution_grants).

Failure diagnostics return to the main model without passive approval or replay. The model checks partial effects and submits remaining work. Explicit `escalated: true` plus justification remains a compatibility route for one bare execution, cannot be combined with precise grants, and does not preserve hard denies in that bare process.

The current macOS availability check in `sandbox/mod.rs` is an existence check
for `/usr/bin/sandbox-exec` — **not** a real capability probe like Linux/Windows.
Unavailability takes the common manual path. The `sandbox-exec` deprecation risk
is accepted; future system compatibility needs continuous native re-verification.

## 3. Progress and acceptance

Rules/Seatbelt/native-read approval, GUI file persistence, and guards with
same-turn injection are implemented. The original profile escaping, path
handling, process-group termination, and smoke framework are reused; the old
network-rejection test was changed to an open-network expectation.

`auth.json` was temporarily removed from the overrides (COMMON §3.1), so older
"auth read-deny PASS" records do not represent current capability.

Run on real macOS at the candidate commit (tests must be run explicitly with
`--ignored`; skipping is not passing):

```bash
cargo test -p future-agent --test sandbox_smoke -- --ignored --test-threads=1 --nocapture
```

Keep the full commit, OS/arch, and logs. Must check: workspace/temp writes
allowed, external writes fail, read/write denial for existing and newly created
secrets, direct rule-file writes and renames denied, symlinks pointing outside
the workspace cannot bypass via path aliasing, Unicode/escaped paths,
cargo/git/python, open network, timeout/abort descendant cleanup. Additionally
check active/passive titles, rejection not re-run, one-time allowance not
changing later protection, and no persistent allowance for native sensitive
reads.

macOS has no private completion-report channel comparable to Linux's; do not
assume Linux's report semantics apply here.

## 4. Differences, gaps, and follow-up plan

| Priority | Work / boundary |
|---|---|
| P1 | execution_grants integrated; native validation must cover read/write scopes, deny carveouts, single consumption and path changes during approval. See COMMON §5.1 |
| P1 | Until the `auth.json` trusted-credential channel is complete, the read risk of the temporarily removed override remains |
| P1 | Whole-rule-file read/parse failure behaves differently on macOS than Linux's compile fail-closed; evaluate unified diagnostics and handling, with separate design for individual invalid entries |
| P2 | Raise availability from an existence check to a bounded real probe; expand the denial negative corpus and system-upgrade smoke |
| P2 | Audit new subprocess integration against the actual tool set; build the dev-tool compatibility matrix while continuously narrowing broad mach/IPC grants |
| Accepted | Open network, off-list sensitive content can be exfiltrated, `.git` writable, temp open per actual roots, sandbox-exec deprecated; not treated as resolved security issues |

Seatbelt itself can add temporary per-command path allows; the implementation now uses isolated execution_grants instead of replaying the whole command after failure. The Windows separate-user
candidate approach is unrelated to this platform and must not be mixed into the
macOS changes.
