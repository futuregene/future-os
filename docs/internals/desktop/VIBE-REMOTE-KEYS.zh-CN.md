# 遥控器按键对照清单与自查入口

[English](VIBE-REMOTE-KEYS.md)

状态：**清单与自查入口已就位；实测矩阵为空，全部标「未测」。**

这份文件只有一件事要做：把「某个键真的会发什么」从推测变成实测记录。面板的键位设计（`VIBE.md` §9）建立在一组假设之上，而**其中没有一格被真机验证过**。所以：

* 下面第一张表是**对照清单**——遥控器上每个键，以及它按浏览器规范**可能**产生的 `key` / `code` / 修饰键。这一列是**参考，不是结论**，凡是依型号而变的都写「视型号而定」。
* 第二张表是**实测矩阵**——只填实测值。没测的格子留空并写「未测」，不写任何推测值。
* 每条实测记录都要写明**由谁、何时、哪台机器（OS + 桌面端版本）、哪个型号**。

## 一、对照清单（一页，可打印）

打印这张表，按遥控器实际按键逐行填空。`⌥⇧K ×3` 打开面板里的自查读数（见下一节）。

| # | 遥控器按键 | 期望 `code` | 期望 `key` | 修饰键 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | 上 | `ArrowUp` | `ArrowUp` | 无 | 按住时系统重复（读数里出现 `repeat`） |
| 2 | 下 | `ArrowDown` | `ArrowDown` | 无 | 同上 |
| 3 | 左 | `ArrowLeft` | `ArrowLeft` | 无 | 同上 |
| 4 | 右 | `ArrowRight` | `ArrowRight` | 无 | 同上 |
| 5 | 确定 / 中键 | `Enter` | `Enter` | 无 | 少数型号发 `NumpadEnter` |
| 6 | 返回 | `Escape`，或 `BrowserBack` / `GoBack` | 视型号而定 | 无 | 三种都接过；以读数为准 |
| 7 | 主页 | `Home`，或 `BrowserHome` | 视型号而定 | 无 | 部分型号什么也不发 |
| 8 | 菜单 | `ContextMenu`，或不发 | 视型号而定 | 无 | **最不稳定的一键**；不发时面板菜单只能靠键盘 `⌘⇧K` |
| 9 | 音量 + | `AudioVolumeUp` | 视型号而定 | 无 | macOS 通常被系统消费，读数里可能始终不出现 |
| 10 | 音量 − | `AudioVolumeDown` | 视型号而定 | 无 | 同上 |
| 11 | 语音 | 通常不发到网页 | — | — | 走系统语音助手 |
| 12 | 电源 | 通常不发到网页 | — | — | 触发系统睡眠，**不绑定** |

关于这张表的四点：

* **`code` 是物理键，`key` 是布局产出的字符。** 应用匹配 `code`（`lib/keybinding.ts`）；`key` 只在有的引擎不发 `code` 时兜底。所以 `code` 那一列才是键位真正依赖的东西。
* **「视型号而定」不是偷懒。** 同一颗丝印为「菜单」的键，有的型号发 `ContextMenu`，有的发 `F12`，有的什么都不发——这正是 `VIBE.md` §9.3 的降级表存在的原因。
* **音量键与电源键即便在读数里出现，也不要写进键位表**，除非同一型号在目标平台上稳定出现三次以上。
* **按住方向键时读数会出现 `repeat`**：这不是错误，是遥控器导航赖以工作的长按连发。

## 二、怎么做（沙发上的三步）

1. **让读数出现。** 开发构建里直接连按三次 `⌥⇧K`；打包构建需要先允许一次：在开发者工具里执行
   `localStorage.setItem("future.vibe.keyProbe", "1")`，重新打开面板再连按三次 `⌥⇧K`。
2. **按遥控器的键。** 读数浮在面板右下角，只显示、不拦键——按方向键面板照常移动，这一点是刻意的：
   如果它拦键，测出来的行为就不是真实行为了。
3. **抄下来。** 每行是 `key="…" code="…" mods=…`，点「复制」一次拿走六条，贴进第二张表。

读数**永远不参与命令分发**：它没有命令 id、不进命令表、不改变 `dispatch` 的判定顺序；它用冒泡阶段的
监听读事件，从不 `preventDefault` / `stopPropagation`。

## 四、填完之后要改什么

1. 上面第三节这张表——只加实测行，不改别人测过的行。
2. `VIBE.md` §9.2 的「遥控器键 → 层 → 命令」表：某一层如果因为实测而改变（例如某型号的「确定」其实发
   `NumpadEnter`），改的是命令表里的 `aliases`，不是文档里的说法。
3. `VIBE.md` §9.3 的降级表：实测发现某型号确实没有「菜单」键时，那一行从「计划」变成「已证实」。
4. `VIBE.md` §11 的矩阵：从空表变成本文件的第三节（或在这里填完、在那里引用）。

**不要**为了让表看起来完整而填推测值。一张写着「未测」的表，比一张写着错值的表有用得多——后者会让下一
个人按错误的键位去设计。
