# FutureOS Mobile

FutureOS Mobile 是桌面端 Remote 功能的原生移动终端。当前支持 Android 和
iOS；业务层、主题、国际化和凭证存储均保持跨平台。
鸿蒙手机通过卓易通运行 APK 不等于鸿蒙原生客户端，系统选择器及跨应用文件操作的边界见
[鸿蒙兼容性核查](harmonyos-compatibility.zh-CN.md)。

用户安装与配对流程见 [手机远程指南](../../wiki/zh/Remote.md)；本页面向源码开发与分发维护。

## 当前能力

- 扫描桌面端一次性二维码配对，也支持手动粘贴配对码。
- 一台手机可保存多个 Desktop 配对并切换使用；每个 Desktop 仍只允许一台手机配对。
- 使用设备独立 NKey、短期 JWT 和刷新 token 连接远程 NATS。
- 显示桌面在线状态与会话列表，新建或继续桌面对话。
- 流式展示回复、思考与工具执行；支持审批、停止、模型、思考等级和重命名。
- 会话支持置顶、重命名、单条删除和多选批量删除；可整块删除工作区（连同其中
  的会话，桌面端工作区目录里的文件不会被删），工作区的折叠状态会跨重启保留。
- 工作区本身也可置顶（工作区列表的分组菜单）。置顶的工作区分组排在置顶会话之后、
  所有未置顶工作区之前；标记存储在桌面端，重新配对后仍然保留，工作区标签页按它排序。
- 历史分页加载、按 `(runId, idx)` 去重，并在连接恢复后通过
  `get_events_since` 回补实时事件。
- 支持从系统相册选择或调用系统相机拍摄图片、通过系统文件选择器添加文件附件；
  可下载会话附件并在手机预览图片、Markdown、文本和 JSON，其余受支持类型交给
  系统应用打开、保存或分享。预览页也可分享原文件或用其他应用打开，缺少阅读器不会
  阻止保存和分享。
- 会话顶部的文件夹按钮可查看当前会话在桌面端的目录，进入子目录、返回上级、
  刷新列表或切换隐藏文件；点击文件复用手机预览/系统打开流程。
- Android 支持从其他应用**分享**文字/图片/文件进来；iOS 新增原生 Share Extension，
  保存后打开 FutureOS 导入文字/链接/图片/文件。可以新建普通/工作区会话，也可以选择已有
  会话；内容追加到目标会话草稿，保留原有文字和附件，确认前不上传、不自动发送。iOS 的保存/外部打开也分别接入原生文档选择器/Open In；
  旧原生包保留分享面板回退。扩展需 Apple App Group 和独立签名 profile，且须显式设置
  `FUTURE_IOS_SHARE_EXTENSION=1` 启用；现有发版工作流不变、默认不打包扩展。
  详见 [iOS 能力与签名配置](ios-platform-parity.zh-CN.md)。
- seed、JWT 和刷新 token 分项存入 Android Keystore 支持的 SecureStore；
  明文不会进入 AsyncStorage、日志或二维码。

## 界面语言

- 默认「跟随系统」：系统首选语言为中文（含简体、繁体地区）时使用中文界面，其他语言使用英文。
- 会话列表的「设置 → 语言」可选择「跟随系统 / 中文 / English」；未配对时也可在配对页面底部选择。
- 手动选择立即生效并保存在本机，重启、切换桌面或断网不会改变选择。
- 选择「跟随系统」后会立即重新读取系统语言；在系统设置中更改语言，回到应用时自动同步。

## 聊天提示与更新提醒

- 输入区保留两排：文本输入一排，模型、思考模式、技能 `/`、附件和发送/停止按钮共用一排。
  小于 360pt 或大字号时，模型与思考合并为「模型设置」入口，操作按钮保持 44pt 触控区域。
- 在消息开头或空白后输入 `/`，或点击附件左侧 `/`，可展开输入框上方的技能候选。
  输入关键词按技能名、描述及可用的中文元数据筛选；选中只插入 `/技能名 `，不自动发送。
  关闭候选保留草稿，URL 和带分隔符的路径不会触发补全。候选打开时刷新当前 Agent
  的已安装技能目录（远程只读 `list_skills`，握手能力 `skills_v1`）；旧桌面端提示升级，
  仍可手动输入完整命令。
- 聊天顶部显示「工作区 · 名称」或「非工作区会话」，新建后尚未发送消息时也会显示。
- 配对连接成功后申请系统通知权限。当前桌面的任务完成或失败时会提醒，当前打开的
  会话也不例外；手动停止不发完成通知。系统通知不包含消息正文；未授权时前台使用
  应用内提示。实时事件和会话快照共同检测结束状态，避免短任务漏掉或重复快照提醒。
- 这是**本地通知，不是离线推送**。iOS 构建不声明 APNs 推送能力，Android 构建不声明 FCM 接收权限；普通切后台保留至多 5 秒的快速返回宽限，相册／相机／
  文件选择器保留至多 60 秒；之后释放远程连接。操作系统也可能更早暂停 JavaScript。
  已观察到运行中的任务，
  回到前台同步到完成状态后才会提醒。App 被系统关闭后无法保证实时通知，重新启动
  也不会把历史完成记录全部弹出。通知权限与勿扰设置由手机系统管理。
- 启动、回到前台及持续使用时自动检查更新（成功检查间隔 6 小时，网络失败后重试）。
  同一版本在本次启动中只提示一次；确认后沿用 Android 安装包 / iOS App Store 更新
  流程。本地开发包仅打开下载链接；TestFlight 更新仍由 TestFlight 管理。
- 更新弹窗将当前版本与可用版本分行展示，保留构建编号或提交哈希，并标明测试、每夜、
  开发或本地构建。开发/本地构建不将每夜构建声称为更新的版本；按钮区分浏览器下载、
  Android 下载并安装和前往 App Store。

新增了 `expo-notifications` 原生依赖，已有开发客户端需要重新构建安装，仅刷新 JS 不够。

长期后台、锁屏或进程被系统终止后的可靠提醒，仍需要平台侧推送投递、设备 token 注册及
APNs／Android 推送配置；当前没有这条链路。不能把通知权限已授权或短时间保持 WSS
理解为具备离线推送。

### 界面与连接回归检查

- 删除会话、批量删除、删除工作区、解除桌面配对统一使用 `DialogSurface` 与公共按钮；
  会话重命名在 iOS/Android 使用相同表单，下载进度也复用该弹窗表面。
- Android 提示弹窗正文禁用原生文本选择，避免 OEM 的选择控件灰底；iOS 保留文本选择。
  两端仍可滚动阅读完整提示。真机需覆盖下载/更新弹窗、长文本、大字号与横屏。
- 用户主动打开或下载小于 1 MiB 的文件时，不再弹移动流量确认；达到 1 MiB 时，移动
  网络与网络类型未知分别提示，网络检测失败按未知处理。Wi-Fi/以太网与缓存命中不提示。
  附件、文件链接、原文件保存/分享和 Markdown 图片使用同一规则，不自动预取。
- 附件来源和文件打开/保存/分享菜单复用 `ActionMenu`；选择来源后等待菜单关闭，再调用系统
  相机、照片或文件选择器。Android 相册走 `PickVisualMedia`（由系统选择兼容回退），
  不再优先调用 `ACTION_PICK` 打开任意第三方图库。系统权限窗和系统选择器仍由 OS 绘制。
- 会话返回列表时保留列表实例和滚动位置，不再重新播放列表的反向进入动画。
  工作区与对话列表中，独立会话保持紧凑留白，不随其他会话出现或展开子会话而加宽；
  只有父会话显示展开按钮，子会话的标题与父会话标题同列。
  父会话的展开按钮是 +/− 树节点开关（收起 `+`、展开 `−`；chevron 仍是工作区分组标题的折叠图标，
  两者同在 8–24 列，靠图标区分），与工作区标题的折叠箭头显然不同：形状是唯一可靠的区分。
  列规则与桌面一致（见 `docs/internals/desktop/PRODUCT.md` §5.2）：行首 8，每层 +20（开关列 16 + 间距 4），
  开关布局宽 16、44×44 触控区用 `hitSlop` 补齐（左侧 16 补进列表内边距、右侧 4 止于标题列，不遮盖标题）。
  工作区分组头使用 4px 的 folder→名称间距，使分组名与其第一层会话标题同列。
- 输入区仍为文本与工具栏两排；窄屏合并模型设置，不压缩操作按钮热区。
- 技能回归：手打与按钮插入 `/`、中文搜索、正文中间替换、关闭/返回键、加载失败重试、
  切换桌面时迟到的技能结果、键盘弹出后的窄屏/大字号布局。自动化覆盖交互与边界；
  iOS/Android 的原生光标和软键盘行为仍需真机验证。
- iOS `inactive → active` 的临时覆盖层不触发全量恢复；真正后台返回仍检查通道。
  网络路径变更先检测现有连接。认证心跳消失则恢复加密通道，不能仅以中转服务的 PONG
  判断 Desktop 正常。候选连接失败时，只有旧通道通过加密双向 RPC 验证，才恢复可操作状态。

真机复测：滚动列表后反复进入/返回；在工作区和对话列表展开子会话，检查同组及其他组的
独立会话留白不变，并覆盖搜索和多选状态；打开/取消
三种附件来源；快速切后台；切换 Wi-Fi/蜂窝；Desktop 重启后等待自动恢复。
特别检查「收到新会话但徽标仍为黄色」：正常加密命令通道恢复后徽标和操作应一起恢复；
仅能接收单向事件、命令无法应答时不能误报绿色。自动化测试替代不了真机选择器及锁屏测试。

### 最新内容同步与流式呈现

进入 streaming 会话的分页延迟基准、优化结果及真机分阶段日志说明见
[同步性能测量](streaming-sync-performance.zh-CN.md)。冷启动／缓存失效改为“语义快照 + 增量”的协议、兼容边界和真实数据 A/B 结果见
[快照恢复优化](streaming-sync-snapshot-optimization.zh-CN.md)。历史仍只加载最近三个用户 exchange，向上翻页再加载更早内容；完整缓存重开仍仅补增量。

- 重开会话时即使已有缓存消息，也显示“正在同步最新内容…”，直到状态、历史与事件回补
  完成；失败重试或等待连接恢复时保留相应提示。此状态与“模型正在生成”分开。
- 提示浮在时间线上方，不插入列表行，不因提示出现/消失改变滚动位置。
- streaming 文本仅对新增后缀逐批显现，单次显现窗口约 192ms，新 Markdown 块约 180ms
  淡入；初次显示的缓存历史不重新打字，已显示块不随每个 token 重播动画。复制及文件操作
  仍使用原始数据。系统减少动态效果开启时不渐进显现或淡入。
- 保持原有阅读锚定：用户查看旧消息时不强制滚到底部。复杂表格、图片加载和折叠屏尺寸
  变化仍需真机检查，不能把自动化逻辑测试当作动画流畅度测试。

## 环境

- Node.js 24 或更高版本（与仓库根目录 `.nvmrc` 和 CI 保持一致）。
- Android Studio、JDK 17 和 Android SDK / Build Tools 36。
- 一台启用开发者模式与 USB 调试的 Android 设备，或 Android 模拟器。

项目版本由仓库根目录 `scripts/version.mjs` 生成，与桌面端使用同一版本真源。
配对控制面的地址由桌面二维码中的 `claim_url` 决定，不再由 APK 的开发/正式
版本选择。同一个 APK 可分别配对 `https://future-os.cn` 和
`https://test.future-os.cn` 的桌面端；续期及撤销地址随各桌面的凭证保存，
切换桌面时不会混用环境。已有配对不受影响，应用更新渠道仍由版本决定。

二维码只允许这两个可信 HTTPS 域名和精确的配对领取路径；任意第三方域名、
非 HTTPS 地址、非默认端口、URL 用户信息及附加查询/片段都会被拒绝（PA003）。
二维码只用于选择可信服务，不允许任意地址访问。

NATS 一律走 `wss://`（TLS）连接：测试与生产环境均不下发明文 `ws://`
地址，客户端在收到非 `wss://` 地址时会拒绝配对。Android 不再允许
cleartext traffic。

## 手工运行 Android

```bash
cd mobile
npm install
npm run android:device
```

也可以从仓库根目录执行：

```bash
make run-mobile-android
```

Expo 会在本地生成被 `.gitignore` 忽略的 `mobile/android/`，然后编译并安装
debug APK。

首次启动后：

1. 在 FutureOS 桌面端登录，打开 Remote，点击“配对并启动”。
2. 手机授予相机权限并扫描桌面端二维码。
3. 配对成功后选择一个桌面会话，或创建新对话。

二维码有效期为 5 分钟且只能使用一次。解除设备配对后必须重新扫码。

### 浏览会话文件

进入已有会话，点击顶部的文件夹按钮打开“会话文件”。面板显示桌面端的当前会话
目录（不是手机本地目录）；点击文件夹进入，使用“返回上级”或“会话根目录”导航。
支持手动刷新和隐藏文件开关，工作区会话默认显示隐藏文件。Android 系统返回键／边缘
返回手势先逐级返回上级目录，到根目录后才关闭文件面板。顶部返回按钮始终直接回到聊天；
文件预览关闭后仍保留当前目录。

此功能需要手机和桌面端均更新，桌面端在线；未发送首条消息的新会话没有文件入口。
图片、Markdown、文本和 JSON 可在应用内预览，其他受支持类型使用系统打开/保存/分享
流程，沿用现有 10 MiB 下载上限与文件类型白名单。不支持的文件类型会提示。
目录浏览限于当前会话根目录及其子目录，受保护的 FutureOS 凭证文件和指向根目录外
的符号链接不会列出。再次点击文件会重新校验内容标识，以免显示旧缓存。

### 添加和切换多个桌面端

点击会话列表顶部的桌面标识（或设置中的“已配对的桌面端”），选择“扫码添加桌面端”，
扫描另一台 Desktop 的二维码。已有配对不会被覆盖，之后点击列表中的桌面端即可切换，
无需重新扫码。应用启动后恢复上次选择的 Desktop；同一时刻只操作所选 Desktop，
不汇总其他 Desktop 的实时会话。

列表里每个桌面端都有一个铅笔按钮可以改名字；名字只保存在本机，不会同步到 Desktop
或平台，清除名字后重新显示 Desktop 的 id。列表在宽屏上居中并保留左右留白。

解除配对仅移除选中的 Desktop，不影响其他配对。Desktop 侧的一台手机限制保持不变：
更换手机仍需重新生成二维码配对，旧手机绑定按原有服务端规则撤销。
旧版单 Desktop 凭证会自动迁移到新列表，无需重新配对。

凭证按 Desktop 分项保存在 SecureStore，并以单一索引提交完整凭证与当前选择。
切换时清理会话目录和时间线，草稿按 Desktop、待确认的发送/续跑按配对隔离。
旧版待确认操作只迁移到它原有的配对，不会发送到新 Desktop；旧版未隔离的普通草稿不自动迁移。

## iOS 开发

`app.config.ts` 已配置 bundle identifier（`cn.futureos.mobile`）、最低系统版本
（iOS 16.4）、相机权限和 SecureStore/Keychain；React Native 业务层不依赖
Android 专属 API，Android 与 iOS 共用同一套配对、会话和聊天逻辑。

首次开发 iOS 前需安装 Xcode 及对应 iOS 模拟器运行时。`mobile/ios/` 由
`expo prebuild` 生成，是本地构建产物，已被 `.gitignore` 忽略、不提交。

### 环境

- macOS + Xcode（含 iOS SDK 与模拟器运行时）。
- iOS 16.4 或更高版本的模拟器或真机。

### 手工运行 iOS（模拟器）

```bash
cd mobile
npm install
npm run ios
```

也可以从仓库根目录执行：

```bash
make run-mobile-ios
```

或者使用一键启动脚本（自动创建/启动模拟器、装依赖、prebuild 并运行）：

```bash
scripts/start-mobile-ios.sh          # dev 模式（Metro + debug 构建）
scripts/start-mobile-ios.sh release  # release 模式（独立运行，无需 Metro）
```

### 手工运行 iOS（真机）

将 iPhone 通过 USB 连接 Mac，在 Xcode 中选中开发团队后：

```bash
cd mobile
npm run ios:device
```

免费 Apple ID 即可真机调试；提交 App Store 需要付费 Apple Developer 账号。

### GitHub Action TestFlight 分发

主分发路径是由 `build.yml` / `release.yml` 协调调用的可复用工作流
`.github/workflows/build-ios-testflight.yml`，构建签名 `.ipa` 并上传 TestFlight：

1. 在 GitHub 仓库 Settings → Secrets 配置：
   - `IOS_DIST_CERT_P12_BASE64` / `IOS_DIST_CERT_P12_PWD` — iOS Distribution 证书。
   - `IOS_PROVISIONING_PROFILE_BASE64` — 主 App 的 App Store provisioning profile。
   - Share Extension 默认不进入现有发版；启用需要独立 profile 和后续签名流程配置，
     见 [签名配置](ios-platform-parity.zh-CN.md)，本次不修改工作流。
   - `APPLE_API_KEY` / `APPLE_API_KEY_ID` / `APPLE_API_ISSUER` — App Store Connect API Key。
2. 通过构建/发布协调工作流触发；iOS 子工作流不单独手动触发。
3. 协调工作流传入纯数字 marketing version 与递增 build number。
4. 上传后在 App Store Connect → TestFlight 管理测试者，外部测试可能需要 Beta 审核。
5. 测试者通过 TestFlight 邀请安装 FutureOS。

> 本地测试包由 `scripts/version.mjs` 生成，可带开发后缀；TestFlight 版本必须为纯数字，

### iOS 平台注意

- Bundle identifier 统一为 `cn.futureos.mobile`，供 Android 与 iOS 共用。
- NATS 一律走 `wss://`，不配置任何明文/cleartext 例外；iOS 依赖系统 ATS
  默认放行 TLS WebSocket，Android 保持 cleartext 禁止。
