# 移动端 Markdown 展示检查

检查日期：2026-09-14。覆盖助手消息（含流式片段）和 Markdown 附件预览；不是 Android/iOS 真机验收报告。

## 渲染链路与边界

- `TimelineCard` 的助手文本片段、无片段助手消息 → `MarkdownText`。
- `PreviewModal` 的 Markdown 文件 → 同一 `MarkdownText`，启用 `file-preview` 模式。
- `@future-os/markdown` 使用 Remark + GFM + 数学语法插件，转换为共享节点；移动端以 React Native `Text` / `View` / `Image` 渲染，**不是浏览器 HTML 渲染器**。
- 用户消息有意按纯文本显示（仅解析文件引用和外部链接）；思考过程、工具输出也不是完整 Markdown 渲染入口。不将这些产品边界误报为助手 Markdown 故障。

## 确认并修复的问题

| 项目 | 原因 / 修复 |
| --- | --- |
| H1–H6 层级丢失 | 共享解析器把 H4–H6 压成 H3；移动端又把 H1/H2 合并。保留六级语义，移动端区分字号并标记无障碍标题，桌面端同步使用正确标题标签。 |
| 有序列表编号不正确 | 起始编号未进入共享节点，移动端总从 1 开始。保留 `start`（含 0 和嵌套列表），两端消费此字段。移动端标记不再限制为 22 点固定宽度，避免三位以上编号挤压。 |
| 引用式链接错误 | 只收集顶层定义，且后定义覆盖前定义。改为按源顺序遍历嵌套定义，并采用首个定义。 |
| 表格内换行无效 | `<br>` 被当作普通 HTML 文本。仅将无属性的 `<br>` / `<br/>` / `<br />`（不区分大小写）转换为换行；其他 HTML 仍安全地显示为字面文本。 |
| 脚注无法对应正文 | 引用保留 `[^id]`，但脚注正文变成无标识引用块。正文补回相同标识；这仍是可读降级，不是完整脚注交互。 |
| 宽表格挤成窄列 | 原先所有列用 `flexBasis: 0` 平分屏幕。整表增加横向滚动，列宽统一且有最小值，随容器宽度和系统字号更新；缺失单元格仍补齐。 |
| 代码排版和 iOS 字体 | 原先长行被折行，通用 `monospace` 不适合作为 iOS 字体名。增加横向滚动，保留换行/缩进/选择复制，显示代码语言；iOS 用 Menlo。 |
| 图片固定框、嵌入 Text | 原先固定 240×160，窄容器可能溢出，宽图/长图留白明显。远程图片移出可选择 Text，按容器宽度和加载后的原始比例展示；保留图片前后的格式、外部链接点击及加载失败文字回退。 |

## 仍未实现 / 有意限制

| 项目 | 当前表现 |
| --- | --- |
| 数学公式 | `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 能被解析，但移动端只显示 TeX 源码，分数/矩阵/上下标没有真正排版。桌面端的 KaTeX DOM 不能直接用于原生 Text。本轮未新增公式引擎。 |
| Mermaid 等图表 | 以代码块显示，不生成图。 |
| 代码语法高亮 | 语言标签和等宽代码可用，但未提供 token 着色或单独的代码复制按钮；原生文字选择和消息复制仍可用。 |
| 脚注、目录锚点 | 脚注有对应标识，但没有上标/跳转/返回；`#anchor` 链接保持不可点击。 |
| 任意 HTML | 除上述内联换行外，HTML（如 `<details>`、`<sup>`、`<img>`）显示源码，不执行。不能为了展示而直接开启任意 HTML / 脚本。 |
| 本地图片 | 后续图片优化已支持点击加载到正文，已有验证缓存时直接展示；文档预览中的图片按原文档目录解析。未缓存图片不静默下载，仍保留打开文件入口。手机自身 URI 文档没有桌面基准目录时不推测路径；不支持的格式仍走原文件入口。 |
| 远程图片格式与网络 | 仅允许 HTTP(S)，具体格式取决于平台 Image 解码器；SVG、网络失败或平台 HTTP 策略可能触发文字回退。本轮没有新增 SVG 解码或放宽网络安全策略。 |
| 文件链接文字 | 后续图片优化已保留原始内联节点，链接内的图片、粗体和其他格式不再丢失。 |

**公式排版**仍是明显的展示缺口。图片已做以下后续优化，但不能以单元测试或浏览器验证代替原生验收。

## 自动化检查

在独立 worktree 内运行：

```text
cd mobile
npm run typecheck
npm run lint
npm test

cd ../desktop
npm run typecheck
npx eslint "src/features/markdown/**/*.{ts,tsx}"
npx vitest run src/features/markdown
```

新增回归覆盖：六级标题、0/非 1 起始编号及嵌套列表、嵌套和重复定义、表格换行及 HTML 安全边界、脚注标识、宽表格列对齐及容器宽度更新、代码保真与平台字体、图片结构/比例/失败后更换 URL、带链接图片的安全点击。

另对标题、嵌套格式、任务列表、引用、表格、引用式链接、图片、数学、代码和脚注样例逐字符追加，逐个前缀比较增量结果和全量解析结果，检查流式完成及文本替换。

首轮结果（PR #609）：移动端 82 个测试文件、1060 项测试全部通过；桌面端完整前端回归 110 个测试文件、968 项测试全部通过；两端 TypeScript 和 ESLint 通过。共新增 19 项测试（移动端 18 项、桌面端 1 项）。

Jest 的模拟布局事件只验证组件结构和尺寸计算，**不能证明 Yoga 原生布局、手势和像素效果正确**。

## 后续图片优化（2026-09-14）

在 `claude/markdown-media` 独立 worktree 上完成；未修改本地 main。

- 共享解析器：递归收集链接内部的本地图片引用；保留本地文件链接标签里的图片/富文本；图片 alt 不再在标签文本提取时丢失。
- 桌面：远程图片失败状态按 URL 隔离，更换 URL 可恢复；非链接图片可重试；长图可展开/收起；预览和工作区路径变更隔离旧资源状态。图片链接保留原点击目标，不嵌套重试/展开按钮；链接图片仍使用缩略显示。已解析的工作区外图片可显式点击加载，但不会自动读盘。
- 移动端：本地图片点击加载进正文；只读取已验证的图片缓存做自动展示；保留大小限制和蜂窝网络确认，不启用模型路径自动下载。会话/桌面改变取消旧请求并阻止旧结果进入新会话；同一图片重复点击不并发下载。
- 移动文档预览：图片路径基于原始桌面文档路径解析，不使用下载到手机的缓存 URI 作为基准。Windows 盘符、反斜杠、相对目录和 `..` 均有测试，真实 canonicalize/授权仍由桌面后端完成。
- 保留原安全边界：桌面工作区外图片不自动读取；危险协议仍拒绝；移动端不能原生解码的图片保留打开原文件入口，不强行以内联 SVG/HTML 执行。

浏览器验证使用真实 `MarkdownContent`、图片组件和全局 CSS，仅对 Tauri IPC 打桩；样例是本地提供的 640×1600 SVG，不涉及真实用户文件。280px 和 640px 两种容器各加载 3 张图（远程、外链包裹本地图、本地链接包裹本地图），折叠高度均为 320px；展开后首图高度约 698px / 1598px；未见图片横向溢出，`a button` 数量为 0，控制台无错误。测试页面和服务在验证后清理。

完整回归：移动端 84 个测试文件 / 1085 项测试，桌面端 111 个测试文件 / 977 项测试通过；两端 TypeScript / ESLint 通过。

尚未执行 Tauri 应用端和 Android/iOS 真机验收；浏览器打桩不能证明真实资产授权、移动网络或原生 Image 解码正确。数学公式、Mermaid、高亮和脚注跳转不在本轮图片改动中，仍维持上表限制。

## 待真机验收清单

当前环境的 PATH、SDK 环境变量及默认用户 SDK 目录均未找到 adb；未运行模拟器/真机，也未将浏览器效果等同于原生验证。

在 Android 和 iOS 分别用聊天回复和 Markdown 附件预览检查：

1. 320/375/430 点左右的窄屏、横竖屏切换、系统大字体：普通段落不越界；4–8 列表格横向滑动时，整张表行列一致，纵向消息滚动仍可用。
2. 包含 200 字符长行、空行、Tab、两空格缩进的代码块：横向可读到尾部，换行与缩进不丢失，长按可复制。
3. H1–H6、粗体中斜体、删除线、行内代码、转义符、硬换行、嵌套引用、列表中多段正文/代码块：格式及顺序正确。
4. `0.`、`9.`、`99.`、`100.` 起始列表和任务列表：编号不重置、不截断；屏幕阅读器识别标题和只读任务状态。
5. 宽图/长图/方图、表格或列表中的图、粗体或链接包裹的图：图片在本容器内；失败时有替代文字；新 URL 能重新加载；外部链接可打开。
6. 流式逐步出现的表格、未闭合代码围栏、链接和公式：没有崩溃，完成后与一次性显示一致；长消息滚动无明显回退。
7. HTTP(S)/mailto 链接、含空格/中文/Windows 盘符的文件链接：按既有路由处理；javascript/data 等不交给系统执行。
8. 对公式、Mermaid、HTML、目录锚点、本地图片和脚注使用上表所列边界验收，避免误判已具备完整支持。
