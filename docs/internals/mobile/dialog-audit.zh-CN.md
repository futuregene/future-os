# 移动端弹窗检查

## 应用内弹窗

| 场景 | 实现与处理 |
| --- | --- |
| 文件下载、导出、分享、外部打开失败 | `AppAlert` → `AppDialogHost` → `useAppDialog` → `DialogSurface`；保留现有下载/预览退出后再显示的时序。错误详情在 iOS 可选中复制；Android 按纯文本渲染，避免 OEM 选择控件背景。 |
| 会话重命名失败、文件列表加载失败、Markdown/消息链接打开失败 | 同一 `AppAlert` 通道，不再调用原生 `Alert`。 |
| 蜂窝网络下载确认 | 同一通道；确认/取消/系统返回都在弹窗关闭后处理，避免下载进度弹窗与确认弹窗抢占。 |
| 升级确认、安装失败、前台通知兜底、iOS toast 替代提示 | 同一通道，允许非 React 调用者提交；多个请求按先后排队，防止错误覆盖未处理的确认。 |
| 桌面与会话管理中的删除、解绑、更新检查及错误提示 | 已使用局部 `useAppDialog`，保持页面 active 控制；复用相同 `DialogSurface` 和按钮样式。 |
| 设置、新建会话、重命名、手动配对、下载进度 | 已使用 `DialogSurface`，无需改成另一套 UI。 |
| 文件操作、附件、模型/思考级别选择、分享导入菜单 | 保留应用风格的底部菜单；相同颜色/间距/圆角 token，但不强行改成居中错误弹窗。 |
| 连接状态详情 | 保留锚定连接状态点的应用内 popover；滚动内容与安全区限制。不是错误确认框。 |
| 文件预览 | 保留全页/pageSheet 阅读界面，不属于提示框。 |

`DialogSurface` 统一遮罩、最大宽度、圆角、安全区、键盘避让与长内容滚动。
长错误在弹窗内滚动，不会挤出关闭按钮；文本在 iOS 可选择（保留原生选择），
Android 按纯文本渲染（避免 OEM 选择控件背景）。
ESLint 禁止业务代码直接从 `react-native` 导入 `Alert`，防止再次引入第二套错误弹窗样式。

## 系统界面边界

系统分享面板、其他应用打开列表、相机/图库/文件选择器、权限请求、Android 短 Toast
仍由系统提供，不应为统一样式而伪造。鸿蒙兼容环境如何显示这些面板仍需真机验证。

## 验证

自动化覆盖：iOS/Android 关闭完成后才执行按钮动作、取消与不可取消、重复关闭事件、
并发错误排队、确认动作再产生错误、长错误详情在共享弹窗容器内滚动
（iOS 可选择文本，Android 纯文本）。
既有 `DialogSurface` 测试覆盖安全区、滚动与键盘处理；无真机截图时不声称已经完成视觉验收。

真机验收：

1. 同一 PDF 连续分享三次；在分享面板取消后再次分享；从接收应用返回后再次分享。
2. 确认接收应用得到真实 PDF、原名称及内容；保存与外部打开仍可用。
3. 触发文件/链接错误，检查与设置/重命名相同的字体、按钮、圆角、遮罩。
4. 大字体、横屏/折叠展开时，长错误能滚动，关闭按钮可达，系统返回可关闭。
5. 蜂窝确认按返回键取消；升级确认后安装失败，两个弹窗依次出现。
