# FutureOS Wiki authoring contract

Use this contract when creating or refreshing `docs/wiki/{en,zh}/`. The wiki is a
user guide, not a release log or a copy of internal design documents. Verify each
claim against current source before writing; old verification notes are dated
snapshots, not authority to skip a check.

## Audience and scope

Describe implemented, visible behavior in plain language. Desktop platforms are
**macOS, Windows and Linux**; Android/iOS are remote clients of a running desktop.
Research/Data navigation remains outside the user guide while hidden. Skills and
Remote are user-facing: do not omit them based on old hidden-feature assumptions.
No separate TUI page is required here; the repository has `docs/tui*.md`. The CLI
page may document `future tui`, `future channel` and `future loop`. Avoid protocol
internals in general app pages; precise transport/defaults belong in CLI and the
repository guides when necessary for troubleshooting.

## Output and links

- Maintain matching English and Chinese filenames and equivalent factual content.
- Link within the same language using `[[Page]]` or `[[Label|Page]]`; update
  `_Sidebar.md` and `_Footer.md`. Do not use Markdown links without `.md` as if
  they were repository-relative files.
- Keep pages independently usable; no cross-language navigation is required.
- `Models.md` is generated by `scripts/generate_models.py` (`make generate-models`),
  never hand-edited. Do not regenerate merely to change surrounding prose.
- Keep README, build/install, directory and security references aligned when a
  shared fact changes. New user-guide pages must be linked from the docs index.

## Facts that must not regress

1. **Approval is not on for every call by default.** Desktop default is `off`;
   fresh agent sessions use permission `all`. An enum default is not an application
   default. Manual path rules can allow ordinary reads/workspace writes; sandbox
   commands need not ask before execution. Separate legacy `--permission` levels
   from `off/manual/sandbox`; `none` denies all tools, not just external writes.
2. **Three OS backends, unequal guarantees.** macOS Seatbelt; native Linux system
   Bubblewrap ≥ 0.9.0; Windows restricted-token write protection. Network is open.
   Linux has no seccomp and missing/dynamic-path detection limits; Windows has
   read/ACL/delete limits. Disclose the `auth.json` exception. Do not turn an
   available probe or old smoke PASS into universal release/security certification.
3. **Local IPC is default.** Unix socket selection honors `FUTURE_AGENT_SOCKET`,
   then Linux `XDG_RUNTIME_DIR`, then the HOME fallback; Windows uses a per-user
   pipe. TCP is explicit. TUI/Desktop may start a sidecar; they only own the agent
   they started, not an externally managed process.
4. **Release vs test builds.** Formal macOS/Windows release workflows sign;
   macOS also notarizes. Unsigned test artifacts have separate guidance.
   `readme-macos.txt` is injected into unsigned DMGs, not evidence that every
   current release is unsigned. Do not recommend bypassing unexplained signature
   failures. Linux has x86_64/aarch64 deb, portable and static CLI release packages;
   local build scripts can differ in naming/linkage. Honor actual artifact names.
5. **Local-first is not local-only.** Model requests, online tools, Remote relay
   and IM bridges transmit data. Mobile enforces WSS; desktop NATS transport is
   deployment-controlled. Do not promise E2EE or universal credential isolation.
6. **Commands match code.** Use Rust sources, not retired `cli/src/*.ts` files.
   Prefer `future channel`; if showing a release binary, build with `--release`.
   Slash commands handled by bridge code can still call the agent over RPC;
   "not sent to the model" does not mean "no agent connection needed".
7. **Counts are not durable.** Derive skill/command/model counts from current
   registries, or avoid exact counts. Preserve historical acceptance reports with
   their original dates/candidate commits and a clear historical-snapshot notice.

## Final checks

Check local links and wiki targets, balanced fences, bilingual page parity,
command flags/defaults, platform/architecture names and release-channel wording.
Search for stale macOS-only sandbox, default TCP, retired CLI TypeScript paths,
blanket approval promises and forbidden-Linux/hidden-Remote instructions. Confirm
that design plans and historical test results are not presented as current facts.
