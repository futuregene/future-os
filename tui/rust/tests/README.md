# TUI Render Parity (TS vs Rust)

Byte-for-byte render comparison between the TypeScript TUI (`tui/src/`)
and the Rust port (`tui/rust/`) for the P2 rendering core: the markdown
renderer (pulldown-cmark adapter), the ChatArea (including the streaming
prefix-cache path) and the terminal-image helpers.

## Harness

```bash
make test-tui-diff            # or: tui/rust/tests/diff-ts-rust.sh
tui/rust/tests/diff-ts-rust.sh --verbose   # show the failing diff
tui/rust/tests/diff-ts-rust.sh --keep      # keep /tmp/future-tui-diff-* artifacts
```

Both sides consume the **shared corpus** `tui/rust/tests/parity-corpus.json`
(generated by `tui/rust/scripts/gen_parity_corpus.py` — regenerate with
`python3 tui/rust/scripts/gen_parity_corpus.py`). Each case renders through
the TS implementation (`tui/render-parity.ts`, run with bun) and the Rust
implementation (`tui/rust/examples/render_parity.rs`, run with cargo), then
the harness byte-compares one line per case:

```
<kind>|<name>|<base64(JSON.stringify(result))>
```

Corpus coverage: 35 markdown cases (headings, tables incl. the column-width
shrink algorithm, quotes, code blocks, lists, hr, strikethrough, links,
definitions, html, blank-line/space rules, CJK wrap, padding, thinking
theme, default text style, kitty-image passthrough, tabs), 18 ChatArea
cases (user/assistant/system/tool/welcome messages, thinking + thinking
hidden, run states, queue position, viewport scrolling, streaming
pending/stopped), 5 chatStream cases (the streaming prefix-cache path) and
39 terminal-image cases (kitty/iTerm2 encoding incl. >4096-byte chunking,
PNG/JPEG/GIF/WebP dimension sniffing, id extraction/collection/deletion,
hyperlink, image fallback, renderImage under all three capability modes).

## Encoding parity

Byte-identity relies on two facts, verified empirically:

1. `serde_json::to_string` escaping matches JS `JSON.stringify` exactly
   (`\u001b`, `\u0007`, `\u001f` etc.; `\u007f`/DEL and non-ASCII pass
   through raw on both sides).
2. Standard base64 with padding (`base64::general_purpose::STANDARD`)
   matches `Buffer.from(..).toString("base64")`.

The corpus keeps every numeric result an integer, so JS number
serialization (which drops a trailing `.0`) cannot diverge from serde_json.

## Bugs the harness caught (all fixed)

- **h1 style composition order** — TS applies `theme.heading(bold(underline(t)))`
  (fg, bold, bold, underline); the port had `heading(underline(bold(t)))`.
  The stale unit test that had encoded the wrong order was corrected.
- **queued suffix inside `dim()`** — TS renders `dim("queued (#n)")` with the
  suffix inside the dim span; the port reset the style before the suffix.
- **paragraph trailing whitespace** — pulldown-cmark trims trailing spaces
  from its `Text` events; marked keeps them (a trailing `text` token). The
  paragraph adapter now restores the source slice's trailing whitespace.

## Accepted divergences (by design)

- **Link reference definitions inside blockquotes/list items** keep their
  surrounding blank-line spacing only at the top level (pulldown-cmark
  consumes definitions differently inside containers). Documented in
  `tui/rust/src/components/markdown.rs`; not exercised by the corpus.
- Live rendering that depends on timestamps / random ids (allocateImageId,
  newId) is excluded from the corpus — ids are supplied explicitly.
