# TUI Render Parity (Rust vs golden)

Byte-for-byte render comparison for the P2 rendering core of the Rust TUI
port: the markdown renderer (pulldown-cmark adapter), the ChatArea (including
the streaming prefix-cache path) and the terminal-image helpers.

## Harness

```bash
make test-tui-diff            # or: tui/tests/golden-diff.sh
tui/tests/golden-diff.sh --verbose   # show the failing diff
tui/tests/golden-diff.sh --keep      # keep /tmp/future-tui-diff-* artifacts
```

The TypeScript TUI was retired (2026-08, same as the CLI): its render outputs
were recorded per corpus case into `tui/tests/golden/parity-ts.golden`
**before** the TS sources were deleted. The harness renders each case through
the Rust implementation (`tui/examples/render_parity.rs`, run with cargo) and
byte-compares the output against the golden:

```
<kind>|<name>|<base64(JSON.stringify(result))>
```

Corpus: `tui/tests/parity-corpus.json` (generated by
`tui/scripts/gen_parity_corpus.py` — regenerate with
`python3 tui/scripts/gen_parity_corpus.py`). Coverage: 35 markdown cases
(headings, tables incl. the column-width shrink algorithm, quotes, code
blocks, lists, hr, strikethrough, links, definitions, html, blank-line/space
rules, CJK wrap, padding, thinking theme, default text style, kitty-image
passthrough, tabs), 18 ChatArea cases (user/assistant/system/tool/welcome
messages, thinking + thinking hidden, run states, queue position, viewport
scrolling, streaming pending/stopped), 5 chatStream cases (the streaming
prefix-cache path) and 39 terminal-image cases (kitty/iTerm2 encoding incl.
>4096-byte chunking, PNG/JPEG/GIF/WebP dimension sniffing, id
extraction/collection/deletion, hyperlink, image fallback, renderImage under
all three capability modes).

Re-recording the golden is only possible from the pre-retirement TS tree
(`bun render-parity.ts <corpus>`); the committed golden is the reference.

## Encoding parity

Byte-identity relies on two facts, verified empirically against the retired
TS implementation:

1. `serde_json::to_string` escaping matches JS `JSON.stringify` exactly
   (`\u001b`, `\u0007`, `\u001f` etc.; `\u007f`/DEL and non-ASCII pass
   through raw on both sides).
2. Standard base64 with padding (`base64::general_purpose::STANDARD`)
   matches `Buffer.from(..).toString("base64")`.

The corpus keeps every numeric result an integer, so JS number
serialization (which drops a trailing `.0`) cannot diverge from serde_json.

## Bugs the harness caught (all fixed)

- **h1 style composition order** — TS applies `theme.heading(bold(underline(t)))`
  (fg, bold, bold, underline); the port had `heading(underline(bold(t)))`.
  The stale unit test that had encoded the wrong order was corrected.
- **queued suffix inside `dim()`** — TS renders `dim("queued (#n)")` with the
  suffix inside the dim span; the port reset the style before the suffix.
- **paragraph trailing whitespace** — pulldown-cmark trims trailing spaces
  from its `Text` events; marked keeps them (a trailing `text` token). The
  paragraph adapter now restores the source slice's trailing whitespace.

## Accepted divergences (by design)

- **Link reference definitions inside blockquotes/list items** keep their
  surrounding blank-line spacing only at the top level (pulldown-cmark
  consumes definitions differently inside containers). Documented in
  `tui/src/components/markdown.rs`; not exercised by the corpus.
- Live rendering that depends on timestamps / random ids (allocateImageId,
  newId) is excluded from the corpus — ids are supplied explicitly.

# tmux Screen Consistency (Rust vs golden, live app)

End-to-end screen comparison of the **full interactive Rust TUI** running in
a real tmux pane against a deterministic mock gRPC agent. This is the P4
gate: the welcome banner, footer (incl. token/cache truthiness), status
overlay, help card, model selector, sessions overlay, prompt reply and
Ctrl+C exit.

## Harness

```bash
make test-tui-tmux            # or: tui/tests/tmux-diff.sh
tui/tests/tmux-diff.sh --record   # rewrite goldens from the Rust pane
tui/tests/tmux-diff.sh --verbose  # show failing diffs
tui/tests/tmux-diff.sh --keep     # keep /tmp/future-tui-tmux-* artifacts
```

The harness starts one mock agent instance (`tui/examples/mock_agent`, a
deterministic `FutureAgent` gRPC server), opens a tmux window (80x36 pane)
with the Rust TUI (`future-tui`), and drives it with keystrokes; at each
scenario step the pane is captured with `capture-pane -p -e` and
byte-compared against the golden:

1. `welcome` — idle screen after connect
2. `typed` — input line with text
3. `reply` — submitted prompt + streamed markdown reply
4. `status` — `/status` overlay (get_state + list_models)
5. `help-overlay` / `help-closed` — `/help` card + Escape
6. `model-overlay` / `model-closed` — `/model` selector + Escape
7. `sessions-overlay` / `sessions-closed` — `/sessions` + Escape
8. `ctrl-c` — the TUI must exit with status 0

**Golden tests**: `tui/tests/golden/<scenario>.txt` records the reference
screens — captured from the retired TypeScript TUI's pane **before** the TS
sources were deleted, then re-verified byte-for-byte against the Rust pane.
Verify mode checks the Rust pane against the golden, so a divergence in the
port OR an intentional screen change (which must be committed together with
re-recorded goldens) is caught. Regenerate with `--record` after an
intentional change (records from the Rust pane).

## Determinism notes

- Mock agent responses are fixed (session state, model list, sessions list,
  streamed reply) so the TUI renders identical content every run.
- The harness waits for the banner (`future-tui v`) before capturing, and
  sleeps 1 s at each step for the 33 ms render scheduler.
- Slash commands use a `submit_cmd` helper: type → wait for the 20 ms
  autocomplete debounce → Enter (applies popup selection) → Enter (submits).
  A single fast Enter would be consumed by the autocomplete popup.

## Bugs the harness caught (all fixed)

- **Footer token stats JS truthiness** — TS renders `↑/↓/R/W` token stats
  only when the value is truthy (`if (this.data.tokensCacheR)`), so a zero
  value is skipped. The port used `if let Some(n)` and rendered `R0 W0` for a
  `Some(0)`; the P1 footer parity test had only used non-zero values.
- **Status overlay session/model fallback** — TS renders
  `**Session:** ${s.sessionId || "(none)"}` (either-or); the port always
  appended ` or (none)`. Same for `**Model:**` with ` or (unknown)`.
